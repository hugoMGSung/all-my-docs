

## 들어가며

이번 과정에서는 스마트 양식장의 수산물 데이터를 모으고, AI 모델로 분석한 결과를 웹 화면에 보여주는 서비스를 만듭니다. 전체 서비스는 데이터를 관리하는 백엔드, AI 추론 서버, 결과를 보여주는 프론트엔드로 구성됩니다.

1일차에는 서비스의 출발점인 **REST API의 구조**와 **Node.js의 요청 처리 방식**을 살펴봅니다. 마지막에는 양식장 모니터링 서비스의 첫 API 서버를 실행하고, 이미지 파일과 데이터베이스 문서를 어떤 방식으로 연결할지 설계합니다.

## 1. 이번 과정에서 만들 서비스

완성할 서비스는 양식장 카메라 이미지와 관측 정보를 저장하고, AI 분석 결과를 대시보드에 표시하는 웹 서비스입니다.

서비스의 데이터 흐름은 다음과 같습니다.

```text
카메라 이미지와 관측 정보
        ↓
Node.js 백엔드 ─── MongoDB
        ↓                 ↑
AI 추론 서버 ─────── 분석 결과
        ↓
React 모니터링 화면
```

Node.js 백엔드는 웹 화면의 요청을 받고 데이터를 관리합니다. AI 추론 서버는 이미지에서 어종이나 개체를 분석합니다. MongoDB는 관측 정보와 분석 결과를 저장하고, React 화면은 데이터를 차트와 이미지로 보여줍니다.

오늘은 전체 서비스 중 Node.js 백엔드의 기본 구조를 이해하고 첫 요청을 처리합니다. MongoDB 연결과 데이터 등록 기능은 다음 수업에서 구현합니다.

## 2. API란?

API(Application Programming Interface)는 프로그램끼리 기능이나 데이터를 주고받기 위한 약속입니다. 웹 서비스에서는 브라우저나 다른 서버가 HTTP 요청을 보내면, 백엔드가 요청을 처리하고 HTTP 응답을 돌려주는 방식으로 API를 구성합니다.

예를 들어 웹 화면이 최근 관측 목록을 요청하면 다음과 같이 동작합니다.

```text
웹 화면 → GET /api/observations → Node.js 서버
웹 화면 ← JSON 응답             ← Node.js 서버
```

여기서 `GET /api/observations`는 관측 데이터를 조회하겠다는 요청을 나타냅니다. API는 어떤 주소에 어떤 방식으로 요청할지, 성공하거나 실패했을 때 어떤 데이터를 돌려줄지 미리 정해 둡니다.

## 3. REST API의 주소와 HTTP 메서드

REST는 웹의 자원을 주소로 표현하고, HTTP 메서드로 자원에 할 일을 나타내는 설계 방식입니다. 주소에는 보통 **관측 데이터**, **양식장**, **장비**처럼 다룰 자원을 표현합니다.

| 작업 | HTTP 메서드 | 주소 예시 | 의미 |
|---|---|---|---|
| 관측 목록 조회 | `GET` | `/api/observations` | 관측 데이터 여러 건 조회 |
| 관측 한 건 조회 | `GET` | `/api/observations/obs-001` | 특정 관측 데이터 조회 |
| 관측 등록 | `POST` | `/api/observations` | 새 관측 데이터 생성 |
| 관측 수정 | `PUT` 또는 `PATCH` | `/api/observations/obs-001` | 기존 관측 데이터 수정 |
| 관측 삭제 | `DELETE` | `/api/observations/obs-001` | 특정 관측 데이터 삭제 |

HTTP 메서드는 요청의 의도를 구분합니다. 같은 `/api/observations` 주소라도 `GET`은 조회, `POST`는 새 데이터 등록을 뜻할 수 있습니다.

다음처럼 동사와 동작을 주소에 반복해서 넣는 방식은 피하는 편이 좋습니다.

```text
GET /getObservations
POST /createObservation
```

자원을 주소에 두고 동작을 메서드로 표현하면 API의 규칙을 일관되게 유지할 수 있습니다.

## 4. 요청과 응답은 JSON으로 주고받기

웹 API는 데이터를 주고받을 때 JSON을 자주 사용합니다. JSON은 객체와 배열 형태로 데이터를 표현하며, JavaScript뿐 아니라 Python 등 여러 언어에서 다룰 수 있습니다.

관측 데이터 한 건을 JSON으로 표현하면 다음과 같습니다.

```json
{
  "observationId": "obs-001",
  "pondId": "pond-01",
  "observedAt": "2026-12-01T09:30:00+09:00",
  "imageUrl": "/uploads/obs-001.jpg",
  "waterTemperature": 24.5,
  "aiResult": {
    "species": "참돔",
    "confidence": 0.94
  }
}
```

`observationId`는 관측 데이터의 식별자이고, `pondId`는 관측이 이루어진 양식장을 나타냅니다. `imageUrl`은 이미지 파일의 위치를 나타냅니다. `aiResult`처럼 관련 정보를 객체 안에 묶을 수도 있습니다.

JSON 응답에는 결과가 무엇을 의미하는지 알 수 있도록 필요한 필드와 자료형을 일관되게 정해야 합니다. 날짜와 시간은 여러 시스템에서 혼동되지 않도록 ISO 8601 형식을 사용하는 것이 좋습니다.

## 5. REST API가 사용하는 HTTP 상태 코드

서버는 응답 본문과 함께 요청 처리 결과를 상태 코드로 알려줍니다.

| 상태 코드 | 의미 | 사용 예 |
|---|---|---|
| `200 OK` | 요청 성공 | 목록이나 상세 데이터 조회 |
| `201 Created` | 새 자원 생성 성공 | 관측 데이터 등록 |
| `400 Bad Request` | 요청 형식이나 값이 잘못됨 | 필수 필드 누락 |
| `404 Not Found` | 요청한 자원이 없음 | 존재하지 않는 관측 ID 조회 |
| `500 Internal Server Error` | 서버 내부 오류 | 예기치 않은 서버 문제 |

상태 코드를 적절히 사용하면 웹 화면이나 다른 서버가 요청 결과를 쉽게 판단할 수 있습니다. 이후 실습에서도 응답 JSON과 상태 코드를 함께 살펴봅니다.

## 6. Node.js란?

Node.js는 브라우저 밖에서도 JavaScript를 실행할 수 있게 해주는 실행 환경입니다. Node.js를 사용하면 JavaScript로 웹 서버를 만들고, 파일을 읽고, 데이터베이스와 통신할 수 있습니다.

브라우저의 JavaScript는 주로 화면과 사용자 입력을 다룹니다. Node.js의 JavaScript는 서버에서 요청을 처리하고 데이터와 파일을 관리합니다. 같은 언어를 사용하더라도 실행되는 환경과 사용할 수 있는 기능은 다릅니다.

Node.js 프로젝트에서 사용하는 외부 패키지는 npm으로 설치하고 관리합니다. 예를 들어 Express는 Node.js에서 HTTP 서버와 API 경로를 간단히 구성할 수 있도록 도와주는 패키지입니다.

## 7. Node.js 이벤트 루프 이해하기

Node.js는 JavaScript 코드를 기본적으로 한 번에 한 작업씩 실행합니다. 하지만 파일 읽기나 네트워크 요청처럼 시간이 걸리는 작업을 기다리는 동안에도 다른 요청을 처리할 수 있습니다. 이를 위해 Node.js는 비동기 작업의 완료를 관리하고, 실행할 콜백을 이벤트 루프를 통해 처리합니다.

다음 코드를 살펴봅시다.

```javascript
console.log("1. 시작");

setTimeout(() => {
  console.log("3. 타이머 콜백");
}, 0);

console.log("2. 끝");
```

실행 결과는 다음 순서로 출력됩니다.

```text
1. 시작
2. 끝
3. 타이머 콜백
```

`setTimeout()`에 0밀리초를 지정해도 콜백이 즉시 현재 코드 사이에 끼어들지는 않습니다. 현재 실행 중인 동기 코드가 끝난 뒤 이벤트 루프가 콜백을 처리합니다.

서버에서 데이터베이스나 외부 AI 서버의 응답을 기다리는 동안 Node.js가 다른 작업을 처리할 수 있는 이유도 비동기 처리 방식에 있습니다. 반대로 오래 걸리는 계산을 동기 코드로 실행하면 이벤트 루프가 막혀 다른 요청의 처리가 늦어질 수 있습니다.

## 8. 첫 번째 Express 서버 만들기

이제 Node.js와 Express로 간단한 API 서버를 만들어 봅시다. Node.js가 설치되어 있다면 터미널에서 버전을 확인합니다.

```bash
node --version
npm --version
```

새 프로젝트 폴더를 만들고 npm 프로젝트를 초기화합니다.

```bash
mkdir smart-aquaculture-api
cd smart-aquaculture-api
npm init -y
npm install express
```

프로젝트 폴더에 `server.js` 파일을 만들고 다음 코드를 작성합니다.

```javascript
const express = require("express");

const app = express();
const PORT = 3000;

app.use(express.json());

app.get("/", (request, response) => {
  response.json({
    message: "스마트 양식장 API 서버가 실행 중입니다."
  });
});

app.get("/api/observations", (request, response) => {
  response.json({
    items: [],
    count: 0
  });
});

app.listen(PORT, () => {
  console.log(`서버가 http://localhost:${PORT} 에서 실행 중입니다.`);
});
```

`require("express")`는 설치한 Express 패키지를 불러옵니다. `express()`로 서버 애플리케이션을 만들고, `app.get()`으로 GET 요청을 처리할 주소를 등록합니다. `response.json()`은 JSON 응답을 보냅니다. `app.listen()`은 지정한 포트에서 서버가 요청을 기다리도록 시작합니다.

터미널에서 서버를 실행합니다.

```bash
node server.js
```

브라우저에서 다음 주소를 열어 JSON 응답을 확인합니다.

```text
http://localhost:3000/
http://localhost:3000/api/observations
```

`/api/observations` 응답은 현재 비어 있는 목록입니다. 다음 수업에서는 이 응답을 실제 관측 데이터와 연결하고, MongoDB에 저장하는 기능을 구현합니다.

## 9. 이미지 파일과 MongoDB 문서 연결하기

카메라가 촬영한 이미지는 크기가 크고, 관측 시간·수온·AI 결과 같은 정보는 구조화된 데이터입니다. 두 종류의 데이터를 저장할 때는 **이미지 원본과 이미지에 대한 설명 정보를 구분해서 관리**하는 것이 일반적입니다.

MongoDB 문서에는 관측 정보와 이미지의 저장 위치를 기록할 수 있습니다.

```json
{
  "_id": "obs-001",
  "pondId": "pond-01",
  "observedAt": "2026-12-01T09:30:00+09:00",
  "image": {
    "fileName": "obs-001.jpg",
    "contentType": "image/jpeg",
    "url": "/uploads/obs-001.jpg"
  },
  "waterTemperature": 24.5,
  "aiResult": {
    "species": "참돔",
    "confidence": 0.94
  }
}
```

이 문서는 이미지 파일 자체를 포함하지 않고, 파일 이름·형식·접근 경로를 저장합니다. 원본 이미지는 서버의 파일 저장소나 오브젝트 스토리지 등에 저장하고, MongoDB 문서가 그 위치를 참조하도록 구성할 수 있습니다. 큰 파일을 MongoDB에 직접 저장해야 하는 요구가 있을 때는 GridFS 같은 방식을 검토할 수 있습니다.

관측 데이터와 이미지의 연결을 설계할 때 다음을 확인합니다.

- 이미지 파일을 식별할 이름이나 ID가 있는가?
- 이미지의 저장 위치를 데이터베이스에 기록하는가?
- 관측 시간, 양식장 ID 등 이미지와 함께 조회할 정보가 정해져 있는가?
- AI 분석 전후의 상태나 결과를 어디에 기록할 것인가?

오늘은 데이터 구조의 원리를 정하고, 실제 파일 업로드와 MongoDB 저장은 다음 수업에서 진행합니다.

## 10. API 설계 시 확인할 점

관측 데이터를 위한 API를 설계할 때는 다음 질문에 답할 수 있어야 합니다.

- 어떤 자원을 다루나요? → 관측 데이터는 `observations`입니다.
- 목록을 조회하는 주소는 무엇인가요? → `GET /api/observations`입니다.
- 특정 관측 자료는 어떻게 식별하나요? → 주소의 ID 또는 데이터베이스의 식별자를 사용합니다.
- 이미지 파일과 관측 정보는 어떻게 연결하나요? → 관측 문서에 이미지 저장 위치나 파일 ID를 기록합니다.
- 서버 처리 결과는 어떻게 알리나요? → HTTP 상태 코드와 JSON 응답으로 알립니다.

API 주소, JSON 필드, 상태 코드가 일관되면 프론트엔드와 AI 서버가 백엔드와 연동하기 쉬워집니다.

## 실습: 관측 상태 API 추가하기

앞에서 만든 `server.js`에 양식장 상태를 돌려주는 API를 추가해 봅시다.

- `GET /api/ponds` 주소를 만듭니다.
- 응답은 JSON으로 작성합니다.
- 양식장 ID, 이름, 수온, 상태 필드를 포함합니다.
- 양식장 두 건을 배열에 넣어 반환합니다.
- 서버를 다시 실행하고 브라우저에서 응답을 확인합니다.

응답 예시는 다음과 같은 구조가 될 수 있습니다.

```json
{
  "items": [
    {
      "pondId": "pond-01",
      "name": "1번 양식장",
      "waterTemperature": 24.5,
      "status": "normal"
    },
    {
      "pondId": "pond-02",
      "name": "2번 양식장",
      "waterTemperature": 27.1,
      "status": "check"
    }
  ],
  "count": 2
}
```

## 핵심 정리

- API는 프로그램끼리 기능과 데이터를 주고받기 위한 약속입니다.
- REST API는 자원을 주소로 표현하고 HTTP 메서드로 작업을 구분합니다.
- JSON은 웹 서비스에서 데이터를 주고받을 때 널리 사용하는 형식입니다.
- Node.js는 비동기 작업을 이벤트 루프로 관리하여 대기 중 다른 요청을 처리할 수 있습니다.
- Express의 경로 처리 함수로 HTTP 요청에 응답하는 API를 만들 수 있습니다.
- 이미지 원본과 관측 메타데이터를 구분하고, 데이터베이스 문서에서 파일 위치를 참조할 수 있습니다.
- 다음 수업에서는 Express API를 확장하고 MongoDB에 실제 데이터를 저장합니다.
