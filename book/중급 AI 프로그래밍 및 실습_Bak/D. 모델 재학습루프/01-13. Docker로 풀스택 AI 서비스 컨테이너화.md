
## 들어가며

앞 장에서는 오분류 자료를 활용한 재학습 프로세스와 모델 버전 관리를 살펴봤습니다. 이번 장에서는 스마트 양식장 서비스를 구성하는 프론트엔드, Node.js API, FastAPI 추론 서버, MongoDB를 각각 Docker 컨테이너로 실행합니다.

컨테이너를 사용하면 각 구성요소의 실행 환경과 의존성을 분리하고, 같은 이미지로 개발·검증·배포 환경을 구성하기 쉬워집니다. 오늘은 각 서비스의 Dockerfile을 만들고 Docker 네트워크로 연결합니다. 여러 서비스를 한 파일에서 함께 실행하는 Docker Compose는 14일차에 다룹니다.

## 1. 컨테이너와 이미지 이해하기

Docker 이미지는 애플리케이션을 실행하는 데 필요한 파일과 설정을 묶은 불변 패키지입니다. 컨테이너는 이미지를 바탕으로 실행된 프로세스입니다.

```text
소스 코드 + 의존성 + 실행 설정
              ↓ docker build
          Docker 이미지
              ↓ docker run
          실행 컨테이너
```

풀스택 서비스를 하나의 컨테이너에 모두 넣기보다, 역할별 서비스로 나누어 실행합니다.

```text
브라우저
   ↓
React 정적 파일 컨테이너 (Nginx)
   ↓ /api 요청 전달
Node.js API 컨테이너
   ├─ MongoDB 컨테이너
   └─ FastAPI 추론 컨테이너
         └─ PyTorch 모델 파일
```

각 서비스는 독립적으로 빌드하고 업데이트할 수 있습니다. 서비스 간 통신은 Docker 네트워크를 통해 컨테이너 이름과 포트로 처리합니다.

## 2. Dockerfile과 빌드 컨텍스트

Dockerfile은 이미지를 만드는 방법을 선언합니다. `FROM`은 기반 이미지, `WORKDIR`은 작업 폴더, `COPY`는 파일 복사, `RUN`은 빌드 단계 명령, `CMD`는 컨테이너 시작 시 실행할 기본 명령입니다.

```dockerfile
FROM node:22-slim

WORKDIR /app

COPY package*.json ./
RUN npm ci --omit=dev

COPY . .

ENV NODE_ENV=production
EXPOSE 3000
CMD ["node", "server.js"]
```

Docker는 빌드 컨텍스트에 포함된 파일을 빌드 엔진에 전달합니다. 불필요한 디렉터리와 비밀정보가 이미지에 들어가지 않도록 `.dockerignore`를 작성합니다.

```text
node_modules
.env
.git
*.log
coverage
```

`.env`를 이미지에 `COPY`하지 않습니다. 비밀 설정은 컨테이너를 실행할 때 환경변수나 플랫폼의 비밀 관리 기능으로 전달합니다.

## 3. Node.js API 컨테이너 만들기

Node.js 서비스의 `Dockerfile`을 API 프로젝트 루트에 작성합니다.

```dockerfile
FROM node:22-slim

WORKDIR /app

COPY package*.json ./
RUN npm ci --omit=dev

COPY . .

ENV NODE_ENV=production
ENV PORT=3000
EXPOSE 3000

CMD ["node", "server.js"]
```

`.dockerignore`도 작성합니다.

```text
node_modules
.env
.git
*.log
```

서버는 컨테이너 외부에서 접속할 수 있도록 `0.0.0.0`에 바인딩해야 합니다. 기존 코드가 `app.listen(PORT)`라면 다음처럼 수정합니다.

```javascript
app.listen(PORT, "0.0.0.0", () => {
  console.log(`API server listening on ${PORT}`);
});
```

이미지를 빌드합니다.

```bash
docker build -t aqua-api:1.0.0 ./api
```

`aqua-api:1.0.0`에서 `aqua-api`는 이미지 이름, `1.0.0`은 태그입니다. 태그를 사용하면 배포할 코드 버전을 구분할 수 있습니다.

## 4. FastAPI 추론 서버 컨테이너 만들기

FastAPI 프로젝트에 `requirements.txt`가 있다고 가정합니다.

```text
fastapi
uvicorn[standard]
torch
pillow
numpy
```

운영 배포 전에는 실제 검증한 라이브러리 버전을 기록해야 합니다. 모델 파일은 이미지에 포함할지, 외부 저장소에서 시작 시 내려받을지 선택합니다. 수업에서는 모델 파일을 `ai_server/models/`에 둔 상태로 이미지에 포함하는 예제를 사용합니다.

`ai_server/Dockerfile`:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt ./
RUN pip install --no-cache-dir -r requirements.txt

COPY . ./ai_server

ENV PYTHONUNBUFFERED=1
EXPOSE 8000

CMD ["uvicorn", "ai_server.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

AI 서버 코드도 `0.0.0.0`에서 요청을 받도록 실행합니다. `.dockerignore`에는 `.venv`, 캐시, 비밀 설정을 제외하고 모델 아티팩트는 이미지에 포함할지 정책에 따라 결정합니다.

```text
.venv
__pycache__
*.pyc
.env
.git
```

이미지를 빌드합니다.

```bash
docker build -t aqua-ai:1.2.0 ./ai_server
```

PyTorch는 이미지 크기를 크게 만들 수 있습니다. CPU와 GPU 환경, CUDA 호환성, 모델 저장 위치를 고려해 이미지 구성과 배포 장비를 정합니다.

## 5. React 프론트엔드 정적 이미지 만들기

React 앱은 빌드 단계에서 정적 파일을 만들고, Nginx 컨테이너가 이를 제공하도록 구성할 수 있습니다. 프로젝트에 `nginx.conf`를 만듭니다.

```nginx
server {
    listen 80;
    server_name _;
    root /usr/share/nginx/html;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }

    location /api/ {
        proxy_pass http://api-server:3000;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

`/api/` 요청은 Nginx가 `api-server` 이름의 컨테이너에 전달합니다. 이 구성이면 브라우저는 같은 도메인으로 웹과 API를 요청할 수 있고, 개발·운영 환경에서 CORS 설정을 단순화할 수 있습니다.

프론트엔드의 `Dockerfile` 예시:

```dockerfile
FROM node:22-slim AS build

WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
```

첫 번째 빌드 단계는 React 파일을 생성합니다. 두 번째 단계는 생성된 정적 파일만 Nginx 이미지에 복사합니다. 개발 도구와 소스 전체를 최종 이미지에 남기지 않아 이미지 구성을 분리할 수 있습니다.

```bash
docker build -t aqua-web:1.0.0 ./web
```

## 6. MongoDB 컨테이너와 영속 볼륨

개발 환경에서는 MongoDB 컨테이너를 실행할 수 있습니다.

```bash
docker volume create aqua-mongo-data
docker run -d `
  --name mongodb `
  --network aqua-net `
  -v aqua-mongo-data:/data/db `
  -e MONGO_INITDB_ROOT_USERNAME=admin `
  -e MONGO_INITDB_ROOT_PASSWORD=change-this-password `
  mongo:7
```

위 예제를 실행하기 전에 Docker 네트워크를 만듭니다.

```bash
docker network create aqua-net
```

볼륨은 컨테이너가 교체되거나 삭제되어도 데이터를 보존하기 위해 사용합니다. 수업과 운영 환경에서는 실제 비밀번호를 예시 값으로 두지 말고, 안전하게 생성한 비밀값을 런타임에 전달합니다.

로컬 데이터베이스는 컨테이너 이름 `mongodb`로 다른 컨테이너에서 접근할 수 있습니다. 배포 환경에서는 관리형 MongoDB를 사용할 수도 있습니다.

## 7. 컨테이너를 Docker 네트워크로 연결하기

컨테이너끼리 통신하려면 같은 Docker 네트워크에 연결합니다.

```bash
docker network create aqua-net
```

각 이미지를 실행합니다. Node.js 컨테이너의 예시는 다음과 같습니다.

```bash
docker run -d `
  --name api-server `
  --network aqua-net `
  -p 3000:3000 `
  -e PORT=3000 `
  -e MONGODB_URI="mongodb://admin:change-this-password@mongodb:27017/?authSource=admin" `
  -e DB_NAME=smart_aquaculture `
  -e AI_SERVER_URL="http://ai-server:8000" `
  -e JWT_SECRET="replace-with-a-secure-runtime-secret" `
  aqua-api:1.0.0
```

FastAPI 컨테이너:

```bash
docker run -d `
  --name ai-server `
  --network aqua-net `
  -p 8000:8000 `
  aqua-ai:1.2.0
```

React/Nginx 컨테이너:

```bash
docker run -d `
  --name web-server `
  --network aqua-net `
  -p 8080:80 `
  aqua-web:1.0.0
```

Node.js 컨테이너 안에서 `localhost`는 Node.js 컨테이너 자신을 가리킵니다. MongoDB나 FastAPI 컨테이너에 연결할 때는 같은 네트워크에 연결된 컨테이너 이름인 `mongodb`, `ai-server`를 호스트로 사용합니다.

## 8. 포트와 서비스 주소 이해하기

Docker의 `-p` 옵션은 호스트 포트와 컨테이너 포트를 연결합니다.

```text
-p 8080:80
   ↑     ↑
호스트  컨테이너
```

브라우저는 호스트의 `8080`에 접속하고, Docker가 요청을 Nginx 컨테이너의 `80` 포트로 전달합니다. 반면 컨테이너끼리 통신할 때는 서비스의 컨테이너 포트와 Docker 네트워크 이름을 사용합니다.

```text
브라우저 → 호스트 포트 8080 → web-server:80
web-server → api-server:3000
api-server → mongodb:27017
api-server → ai-server:8000
```

외부에 공개할 필요가 없는 MongoDB와 FastAPI 포트는 호스트에 공개하지 않고 내부 네트워크에서만 접근하게 할 수 있습니다. 실습의 `-p 8000:8000`은 로컬에서 직접 API를 확인하기 위한 선택 사항입니다.

## 9. 컨테이너 상태와 로그 확인하기

실행 중인 컨테이너를 확인합니다.

```bash
docker ps
```

서비스 로그를 확인합니다.

```bash
docker logs api-server
docker logs ai-server
docker logs web-server
```

컨테이너 안에 명령을 실행하거나 셸을 열어 환경을 확인할 수 있습니다.

```bash
docker exec -it api-server sh
```

서비스가 실행되지 않을 때는 이미지 빌드 오류, 필수 환경변수 누락, 잘못된 내부 주소, 포트 설정, 데이터베이스 준비 상태, 모델 파일 경로를 차례로 확인합니다.

## 10. 데이터와 비밀정보 관리

컨테이너는 교체될 수 있으므로 영구적으로 보존해야 하는 데이터는 컨테이너 파일 시스템에만 두지 않습니다.

- MongoDB 데이터는 볼륨이나 관리형 데이터베이스에 저장합니다.
- 이미지 파일은 영속 볼륨이나 오브젝트 스토리지에 둡니다.
- JWT 비밀키와 데이터베이스 비밀번호를 이미지에 포함하지 않습니다.
- 모델 파일은 이미지 포함, 볼륨 연결, 아티팩트 저장소 사용 중 정책을 정합니다.
- 컨테이너 이름과 이미지 태그에 서비스와 버전을 표시합니다.

## 11. 서비스별 빌드와 실행 흐름

오늘은 Docker 명령으로 서비스를 각각 실행합니다.

```text
1. API 이미지 빌드
2. AI 서버 이미지 빌드
3. React 정적 이미지 빌드
4. Docker 네트워크 생성
5. MongoDB 컨테이너 실행 및 데이터 볼륨 연결
6. FastAPI 컨테이너 실행
7. Node.js 컨테이너 실행 후 내부 주소 확인
8. Nginx 컨테이너 실행
9. 브라우저로 전체 흐름 확인
```

서비스가 많아질수록 각 `docker run` 명령을 직접 관리하기 불편해집니다. 다음 수업에서는 Docker Compose 파일에 서비스, 네트워크, 볼륨, 환경설정을 선언하고 한 번에 실행합니다.

## 오늘의 미션

- 이미지와 컨테이너의 차이를 설명합니다.
- 서비스별 Dockerfile을 작성하고 버전 태그로 이미지를 빌드합니다.
- Docker 네트워크에서 `localhost`와 컨테이너 이름이 가리키는 대상을 구별합니다.
- MongoDB 자료를 볼륨으로 보존합니다.
- 환경변수와 비밀정보를 이미지 안에 넣지 않고 런타임에 전달합니다.
- Nginx가 React 정적 파일과 Node.js API를 연결하는 흐름을 설명합니다.
- 컨테이너 로그와 상태를 이용해 연결 문제를 진단합니다.

## 핵심 정리

- Docker 이미지는 실행 환경을 패키징하고, 컨테이너는 이미지를 실행한 프로세스입니다.
- 풀스택 서비스는 웹·API·추론·데이터베이스를 역할별 컨테이너로 분리할 수 있습니다.
- Docker 네트워크의 컨테이너는 이름과 컨테이너 포트를 사용해 서로 통신합니다.
- 컨테이너 내부에서 `localhost`는 자기 자신이므로 다른 서비스를 가리킬 때 서비스 이름을 사용합니다.
- 데이터베이스와 업로드 파일처럼 보존해야 하는 데이터는 영속 볼륨이나 외부 저장소에 둡니다.
- 비밀번호와 토큰 서명키는 Docker 이미지에 포함하지 않고 실행 시 주입합니다.
- 다음 수업에서는 Docker Compose로 풀스택 서비스를 함께 실행하고 배포 테스트를 합니다.
