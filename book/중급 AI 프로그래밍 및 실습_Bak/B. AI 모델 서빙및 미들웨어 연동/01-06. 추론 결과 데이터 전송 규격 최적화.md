

## 들어가며

앞 장에서는 PyTorch 어종 분류 모델을 FastAPI로 제공하고, Node.js 미들웨어에서 추론 요청을 제어했습니다. 이번 장에서는 모델 결과를 서비스의 다른 부분이 쉽게 이해하고 빠르게 전달받도록 **추론 결과 데이터 전송 규격**을 정리합니다.

모델의 내부 출력값을 그대로 보내면 데이터가 커지고, 화면이나 데이터베이스가 모델의 내부 동작에 강하게 묶일 수 있습니다. 필요한 결과만 안정된 JSON 규격으로 구성하면 통신량과 연동 복잡도를 줄일 수 있습니다.

## 1. 추론 결과 규격이 필요한 이유

FastAPI와 Node.js, React는 서로 다른 역할을 수행합니다. 이들이 같은 결과를 해석하려면 필드 이름과 자료형, 단위, 오류 표현을 합의해야 합니다.

```text
PyTorch 모델 출력
       ↓ 변환
FastAPI 응답 규격
       ↓ HTTP + JSON
Node.js 백엔드
       ↓ JSON
React 화면 / MongoDB
```

응답 규격이 일관되지 않으면 다음 문제가 생길 수 있습니다.

- 어떤 필드가 어종명이고 어떤 필드가 모델 점수인지 알기 어렵습니다.
- 서버가 모델 내부 출력 형태를 바꾸면 프론트엔드도 함께 수정해야 합니다.
- 불필요한 원시 데이터를 계속 전달해 응답 크기가 커집니다.
- 결과에 단위, 모델 버전, 처리 시각이 없어 비교하기 어렵습니다.

## 2. 모델 원시 출력과 서비스 응답 비교하기

모델은 여러 클래스에 대한 logits나 확률 배열을 출력할 수 있습니다.

```json
{
  "logits": [-3.42, 1.18, 0.76, -0.34, 0.29],
  "allProbabilities": [0.01, 0.47, 0.31, 0.10, 0.11],
  "classNames": ["고등어", "광어", "참돔", "방어", "농어"]
}
```

화면에 표시하기 위한 데이터가 상위 두 예측 결과뿐이라면 전체 배열을 전부 보낼 필요가 없습니다. 서비스 목적에 맞는 결과만 정리할 수 있습니다.

```json
{
  "predictions": [
    { "label": "광어", "confidence": 0.47 },
    { "label": "참돔", "confidence": 0.31 }
  ]
}
```

두 번째 응답은 모델의 내부 인덱스와 logits를 노출하지 않습니다. 클래스 이름과 confidence를 전달하므로 React 화면은 모델의 내부 구조를 몰라도 결과를 표시할 수 있습니다.

## 3. 응답 데이터 계약 정하기

API 계약은 요청과 응답의 구조, 자료형, 필수 여부, 오류 규칙을 정리한 약속입니다. 다음을 공통 규칙으로 정합니다.

| 항목 | 규칙 예시 |
|---|---|
| `observationId` | 문자열, 결과와 원본 관측 연결 |
| `status` | `completed`, `review` 등 사전에 정한 값 |
| `predictions` | 점수가 높은 결과부터 정렬한 배열 |
| `confidence` | 0~1 범위의 숫자 |
| `modelVersion` | 사용한 모델 버전을 식별하는 문자열 |
| `inferenceTimeMs` | 추론 소요 시간, 밀리초 단위 |
| `createdAt` | ISO 8601 형식의 UTC 시각 |

자료형과 단위를 문서에 적어 둡니다. `confidence`를 0~1 사이 숫자로 할지 0~100 퍼센트로 할지, 시간은 초인지 밀리초인지 한 가지로 통일합니다.

## 4. 권장 응답 구조 설계하기

어종 분류 API의 응답을 다음처럼 구성할 수 있습니다.

```json
{
  "requestId": "req-8f31",
  "observationId": "obs-001",
  "status": "completed",
  "predictions": [
    { "label": "광어", "confidence": 0.7812 },
    { "label": "참돔", "confidence": 0.1431 }
  ],
  "model": {
    "name": "fish-classifier",
    "version": "1.2.0"
  },
  "timing": {
    "inferenceTimeMs": 42
  },
  "createdAt": "2026-12-01T01:30:00.000Z"
}
```

`requestId`는 요청 하나를 로그와 연결할 때 사용합니다. `observationId`는 양식장 관측 데이터와 연결하는 식별자입니다. 모델 이름과 버전을 포함하면 서로 다른 버전의 결과를 비교할 수 있습니다.

응답에는 모델 내부 텐서나 전체 이미지 원본을 넣지 않습니다. 이미지 파일은 저장소에 두고 URL이나 파일 ID로 참조합니다. 실제 서비스에서 추가 필드가 필요할 때는 기존 필드의 의미와 자료형을 바꾸지 않고 확장하는 방법을 우선 검토합니다.

## 5. 상위 결과만 반환해 응답 줄이기

클래스가 많을 때 모든 확률을 반환하지 않고 상위 `k`개 결과만 전달할 수 있습니다. `k`는 API 목적에 맞춰 정합니다.

PyTorch 추론 코드에서 상위 결과의 개수를 제한하고, 확률 자릿수를 정리합니다.

```python
import time
from datetime import datetime, timezone
from uuid import uuid4

TOP_K = 3
MODEL_NAME = "fish-classifier"
MODEL_VERSION = "1.2.0"


def make_predictions(probabilities, class_names, top_k=TOP_K):
    count = min(top_k, len(class_names))
    scores, indices = torch.topk(probabilities, k=count)

    return [
        {
            "label": class_names[index],
            "confidence": round(float(score), 4)
        }
        for score, index in zip(scores.cpu().tolist(), indices.cpu().tolist())
    ]
```

`round(..., 4)`는 응답의 숫자 자릿수를 일정하게 만듭니다. 내부 연산 정밀도를 낮추는 것이 아니라 전송할 JSON 표현을 간결하게 하는 것입니다. 더 많은 결과가 필요한 분석용 API와 화면용 API는 목적에 따라 다른 `top_k`를 제공할 수 있습니다.

## 6. FastAPI 응답 모델로 규격 고정하기

Pydantic 응답 모델을 사용하면 FastAPI 응답의 필드와 자료형을 코드로 명시할 수 있습니다.

```python
from datetime import datetime
from typing import Literal
from pydantic import BaseModel, Field


class PredictionItem(BaseModel):
    label: str
    confidence: float = Field(ge=0, le=1)


class ModelInfo(BaseModel):
    name: str
    version: str


class TimingInfo(BaseModel):
    inferenceTimeMs: int = Field(ge=0)


class InferenceResponse(BaseModel):
    requestId: str
    observationId: str
    status: Literal["completed", "review"]
    predictions: list[PredictionItem]
    model: ModelInfo
    timing: TimingInfo
    createdAt: datetime
```

`Field(ge=0, le=1)`은 confidence가 0부터 1까지의 범위인지 확인합니다. `Literal`은 `status`에 허용할 문자열을 제한합니다. 응답 모델을 엔드포인트의 `response_model`로 지정하면 API 문서에도 응답 규격이 표시됩니다.

## 7. 응답 시간과 모델 메타데이터 기록하기

추론 시간과 생성 시각을 응답에 포함하면 처리 성능을 관찰할 수 있습니다. 시간 측정에는 시스템 시각 변경 영향을 덜 받는 단조 시계를 사용합니다.

```python
import time
from datetime import datetime, timezone
from uuid import uuid4


@app.post("/predict", response_model=InferenceResponse)
def predict(request: PredictionRequest):
    started = time.perf_counter()

    image = decode_image(request.imageBase64)
    input_tensor = image_to_tensor(image)

    with torch.inference_mode():
        logits = MODEL(input_tensor)
        probabilities = torch.softmax(logits, dim=1)[0]
        predictions = make_predictions(probabilities, CLASS_NAMES)

    inference_time_ms = round((time.perf_counter() - started) * 1000)
    status = "completed"

    if predictions and predictions[0]["confidence"] < 0.55:
        status = "review"

    return {
        "requestId": str(uuid4()),
        "observationId": request.observationId,
        "status": status,
        "predictions": predictions,
        "model": {
            "name": MODEL_NAME,
            "version": MODEL_VERSION
        },
        "timing": {
            "inferenceTimeMs": inference_time_ms
        },
        "createdAt": datetime.now(timezone.utc)
    }
```

위 코드에서 `review`는 최고 confidence가 예시 기준인 0.55보다 낮을 때 확인이 필요하다는 의미입니다. 실제 임계값은 검증 데이터와 운영 기준으로 결정해야 합니다. confidence는 정답일 확률을 보장하지 않으므로, 이를 그대로 확정 판정으로 설명하지 않습니다.

## 8. 오류 응답도 규격화하기

성공 결과뿐 아니라 오류도 일관된 구조로 반환해야 클라이언트가 처리하기 쉽습니다.

오류 응답 예시:

```json
{
  "error": {
    "code": "INVALID_IMAGE",
    "message": "이미지 데이터를 읽을 수 없습니다."
  },
  "requestId": "req-8f31"
}
```

상태 코드와 오류 코드는 각각 역할이 다릅니다. HTTP 상태 코드는 요청이 성공했는지 실패했는지 알려주고, `error.code`는 애플리케이션이 어떤 오류인지 세부 구분합니다.

FastAPI의 예외 처리기에서 공통 오류 형식을 반환하도록 구성할 수 있습니다.

```python
from fastapi import Request
from fastapi.responses import JSONResponse


@app.exception_handler(HTTPException)
async def http_exception_handler(request: Request, exc: HTTPException):
    return JSONResponse(
        status_code=exc.status_code,
        content={
            "error": {
                "code": "INFERENCE_REQUEST_FAILED",
                "message": str(exc.detail)
            }
        }
    )
```

실제 서비스에서는 오류 종류에 따라 `INVALID_IMAGE`, `MODEL_UNAVAILABLE`, `INFERENCE_FAILED`처럼 구분 가능한 코드를 사용합니다. 내부 경로나 스택 트레이스 같은 민감한 상세 정보는 클라이언트 응답에 포함하지 않습니다.

## 9. Node.js에서 규격화된 결과 전달하기

Node.js는 FastAPI에서 받은 응답을 확인하고 필요한 서비스 식별자를 포함해 클라이언트로 전달합니다.

```javascript
app.post("/api/inference/predict", async (request, response, next) => {
  try {
    const aiResponse = await axios.post(
      `${process.env.AI_SERVER_URL}/predict`,
      request.body,
      { timeout: 30000 }
    );

    const result = aiResponse.data;

    if (
      typeof result.observationId !== "string" ||
      !Array.isArray(result.predictions) ||
      !result.model?.version
    ) {
      return response.status(502).json({
        error: {
          code: "INVALID_INFERENCE_RESPONSE",
          message: "추론 서버 응답 형식이 올바르지 않습니다."
        }
      });
    }

    response.json(result);
  } catch (error) {
    if (error.response) {
      return response.status(502).json({
        error: {
          code: "INFERENCE_UPSTREAM_ERROR",
          message: "추론 서버 요청이 실패했습니다."
        }
      });
    }

    if (error.code === "ECONNABORTED") {
      return response.status(504).json({
        error: {
          code: "INFERENCE_TIMEOUT",
          message: "추론 처리 시간이 초과되었습니다."
        }
      });
    }

    next(error);
  }
});
```

Node.js는 FastAPI 응답을 맹목적으로 신뢰하지 않고 주요 필드를 확인합니다. 서버 간 응답이 계약과 다르면 잘못된 결과를 화면에 전달하기 전에 `502` 오류로 처리합니다.

## 10. 전송 크기와 연결 성능 최적화

데이터 전송 최적화는 단순히 압축을 켜는 것만 의미하지 않습니다. 먼저 불필요한 정보를 보내지 않는 것이 중요합니다.

- 필요한 상위 예측 결과만 보냅니다.
- 모델 내부 logits나 중간 텐서는 디버깅 외에는 반환하지 않습니다.
- 이미지 원본을 응답에 넣지 않고 파일 ID나 URL을 사용합니다.
- 숫자의 표현 자릿수와 필드명을 일정하게 합니다.
- 요청·응답 본문 크기 상한을 설정합니다.
- 네트워크 연결을 재사용해 반복 연결 비용을 줄입니다.
- 호출 시간과 응답 크기를 관찰해 병목을 확인합니다.

Axios에서 keep-alive HTTP 연결을 재사용하는 예시는 다음과 같습니다.

```javascript
const http = require("node:http");
const https = require("node:https");
const axios = require("axios");

const inferenceClient = axios.create({
  baseURL: process.env.AI_SERVER_URL,
  timeout: 30000,
  httpAgent: new http.Agent({ keepAlive: true }),
  httpsAgent: new https.Agent({ keepAlive: true })
});
```

연결 재사용은 요청마다 TCP 연결을 새로 맺는 비용을 줄일 수 있습니다. 압축은 응답 크기와 CPU 사용량을 함께 측정한 뒤 적용합니다. 작은 JSON에서는 압축의 이득이 작을 수 있으므로, 데이터 특성과 요청량에 맞춰 결정합니다.

## 11. Postman으로 규격 확인하기

FastAPI 서버와 Node.js 서버를 실행하고 Postman으로 Node.js API를 호출합니다. 응답에서 다음 항목을 확인합니다.

- `observationId`가 요청 값과 일치하는가?
- `predictions`가 confidence 내림차순으로 정렬되었는가?
- confidence가 0~1 범위의 숫자인가?
- 모델 이름과 버전이 포함되었는가?
- 추론 시간이 밀리초로 기록되었는가?
- 낮은 confidence에서 `review` 상태가 반환되는가?
- 잘못된 이미지나 FastAPI 오류가 공통 오류 구조로 전달되는가?

개발자 도구나 Postman의 응답 크기 표시를 이용해 상위 결과 수를 줄였을 때 본문 크기가 달라지는지 비교합니다. 상위 결과의 개수를 1개, 3개, 모든 클래스로 바꿔 확인할 수 있습니다.

## 핵심 정리

- 추론 결과 전송 규격은 서비스 구성 요소 사이의 데이터 계약입니다.
- 응답에는 화면과 후속 처리에 필요한 정보만 포함합니다.
- 상위 예측 결과, 모델 버전, 처리 시간, 생성 시각은 결과 해석과 운영에 도움이 됩니다.

- 오류 응답도 상태 코드와 JSON 구조를 일관되게 정해야 합니다.
- 연결 재사용, 본문 크기 제한, 필요한 필드만 전달하는 방식으로 통신을 효율화할 수 있습니다.
