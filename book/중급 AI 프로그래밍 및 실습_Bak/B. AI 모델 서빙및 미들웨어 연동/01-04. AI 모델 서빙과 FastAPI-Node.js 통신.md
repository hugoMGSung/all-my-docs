
## 들어가며

앞 장에서는 해양 공공데이터를 정제해 MongoDB에 적재했습니다. 이번 장에서는 AI 모델을 다른 프로그램이 요청해 사용할 수 있도록 서버 API로 제공하는 **AI 모델 서빙**을 살펴봅니다.

모델이 이미지나 데이터를 입력받아 예측 결과를 계산하는 과정을 추론(Inference)이라고 합니다. 모델을 서빙한다는 것은 추론 기능을 서버에 올리고, 다른 프로그램이 HTTP 요청으로 이용할 수 있도록 만드는 것입니다.

오늘은 FastAPI로 추론 서버를 만들고 Node.js 백엔드에서 HTTP 요청을 보내 결과를 받습니다. 실제 PyTorch 어종 분류 모델은 다음 수업에서 연결하고, 오늘은 모델 자리에 예제 추론 함수를 두어 서버 간 통신에 집중합니다.

## 1. AI 모델 서빙이란?

학습이 끝난 AI 모델은 파일로 저장해 둘 수 있습니다. 하지만 모델 파일만으로는 웹 화면이나 백엔드가 직접 예측을 요청하기 어렵습니다. 모델을 서버 프로그램에서 불러오고, 입력을 받고, 결과를 정해진 형식으로 반환하는 API를 만들면 다른 서비스가 모델을 사용할 수 있습니다.

```text
React 웹 화면
      ↓ 요청
Node.js 백엔드
      ↓ HTTP + JSON
FastAPI 추론 서버
      ↓
PyTorch 모델
      ↓ 예측 결과
FastAPI → Node.js → React
```

Node.js 백엔드는 서비스 데이터와 웹 요청을 관리하고, FastAPI 서버는 Python 기반 모델 추론을 담당합니다. 각 서버가 역할을 나누면 모델 코드와 웹 서비스 코드를 별도로 개발하고 운영할 수 있습니다.

## 2. 추론 요청과 응답 정하기

서버를 구현하기 전에 요청과 응답의 JSON 규격을 먼저 정합니다. 이번 수업에서는 이미지를 직접 전송하는 대신 이미지 주소와 관측 ID를 받는 예시를 사용합니다.

요청 예시:

```json
{
  "observationId": "obs-001",
  "imageUrl": "http://localhost:3000/uploads/obs-001.jpg"
}
```

응답 예시:

```json
{
  "observationId": "obs-001",
  "predictions": [
    {
      "label": "참돔",
      "confidence": 0.94
    }
  ],
  "modelVersion": "demo-v1"
}
```

규격을 정할 때는 필드 이름, 자료형, 필수 여부, 오류 응답을 함께 합의합니다. Node.js와 FastAPI가 서로 다른 언어를 사용해도 JSON 규격을 지키면 데이터를 주고받을 수 있습니다.

## 3. 동기 처리와 비동기 처리

동기 처리에서는 한 작업이 끝날 때까지 다음 작업이 기다립니다. 비동기 처리에서는 시간이 걸리는 작업을 기다리는 동안 다른 작업을 진행할 수 있습니다.

```text
동기 처리:
요청 A 시작 ───────── 완료
                         요청 B 시작 ─── 완료

비동기 처리:
요청 A 시작 ───────── 완료
      요청 B 시작 ─── 완료
```

HTTP API를 호출하는 코드가 동기 방식으로 실행되어 네트워크 응답을 기다리는 동안 다른 작업을 막으면 서버 처리량이 낮아질 수 있습니다. Node.js에서는 `await`로 비동기 요청의 결과를 기다리되, 이벤트 루프가 다른 작업을 처리할 수 있도록 합니다. Python FastAPI도 `async def`와 비동기 라이브러리를 활용해 네트워크 대기 시간을 효율적으로 다룰 수 있습니다.

여기서 동기·비동기는 요청 결과를 기다리는 코드의 동작을 설명합니다. 별도의 작업 큐를 두고 나중에 결과를 받는 비동기 작업 방식과는 구별해야 합니다. 이미지 분석 시간이 길어 요청 연결을 오래 유지하기 어렵다면 작업 ID를 돌려주는 큐 기반 구조를 검토할 수 있습니다.

## 4. FastAPI 추론 서버 준비하기

Python 가상환경을 사용해 FastAPI와 개발 서버를 설치합니다.

```bash
python -m venv .venv
```

Windows PowerShell에서 가상환경을 활성화합니다.

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS나 Linux에서는 다음 명령을 사용합니다.

```bash
source .venv/bin/activate
```

필요한 패키지를 설치합니다.

```bash
python -m pip install fastapi uvicorn
```

프로젝트 안에 `ai_server/main.py` 파일을 만들고 다음 코드를 작성합니다.

```python
from pydantic import BaseModel, HttpUrl
from fastapi import FastAPI

app = FastAPI(title="Smart Aquaculture Inference API")


class InferenceRequest(BaseModel):
    observationId: str
    imageUrl: HttpUrl


class Prediction(BaseModel):
    label: str
    confidence: float


class InferenceResponse(BaseModel):
    observationId: str
    predictions: list[Prediction]
    modelVersion: str


@app.get("/health")
def health_check():
    return {"status": "ok", "service": "inference"}


@app.post("/predict", response_model=InferenceResponse)
def predict(request: InferenceRequest):
    # 오늘은 서버 간 통신을 확인하기 위한 예제 결과를 반환합니다.
    # 다음 수업에서 이 부분을 PyTorch 모델 추론으로 교체합니다.
    return InferenceResponse(
        observationId=request.observationId,
        predictions=[Prediction(label="참돔", confidence=0.94)],
        modelVersion="demo-v1"
    )
```

Pydantic 모델은 요청 JSON의 필드와 자료형을 확인합니다. `InferenceRequest`는 요청에 관측 ID와 이미지 주소가 있어야 한다고 선언합니다. 응답 모델을 지정하면 결과 구조를 일정하게 유지하는 데 도움이 됩니다.

개발 서버를 실행합니다.

```bash
python -m uvicorn ai_server.main:app --reload --host 127.0.0.1 --port 8000
```

`/health`에서 서버 상태를 확인하고, `/docs`에서 FastAPI가 자동 생성한 API 문서를 볼 수 있습니다.

```text
http://127.0.0.1:8000/health
http://127.0.0.1:8000/docs
```

## 5. Postman으로 FastAPI 요청하기

Postman에서 새 요청을 만들고 다음과 같이 설정합니다.

- Method: `POST`
- URL: `http://127.0.0.1:8000/predict`
- Body: `raw` 선택 후 형식을 `JSON`으로 지정

요청 본문:

```json
{
  "observationId": "obs-001",
  "imageUrl": "http://localhost:3000/uploads/obs-001.jpg"
}
```

요청을 보내고 응답에 `observationId`, `predictions`, `modelVersion`이 포함되는지 확인합니다. 필수 필드를 빼거나 URL이 아닌 값을 `imageUrl`에 넣으면 FastAPI가 유효성 검사 오류를 반환합니다.

Postman은 브라우저 화면을 만들지 않고 HTTP 요청을 보내 API를 확인하는 도구입니다. 서버가 준비되었는지, 요청 JSON이 올바른지, 응답 상태 코드와 본문이 예상한 형식인지 확인할 때 사용합니다.

## 6. Node.js에서 Axios로 FastAPI 호출하기

Node.js 프로젝트 폴더에서 Axios를 설치합니다.

```bash
npm install axios
```

`.env` 파일에 추론 서버 주소를 추가합니다.

```text
AI_SERVER_URL=http://127.0.0.1:8000
```

Node.js의 `server.js`에서 Axios를 불러옵니다.

```javascript
const axios = require("axios");
```

다음 API를 추가해 FastAPI에 요청을 전달합니다.

```javascript
app.post("/api/observations/:id/predict", async (request, response, next) => {
  try {
    const { id } = request.params;

    if (!isValidObjectId(id)) {
      return response.status(400).json({ message: "올바르지 않은 관측 ID입니다." });
    }

    const db = getDatabase();
    const observation = await db.collection("observations").findOne({
      _id: new ObjectId(id)
    });

    if (!observation) {
      return response.status(404).json({ message: "관측 데이터를 찾을 수 없습니다." });
    }

    if (!observation.image?.url) {
      return response.status(400).json({ message: "관측 데이터에 이미지 URL이 없습니다." });
    }

    const aiResponse = await axios.post(
      `${process.env.AI_SERVER_URL}/predict`,
      {
        observationId: String(observation._id),
        imageUrl: new URL(observation.image.url, "http://localhost:3000").toString()
      },
      { timeout: 10000 }
    );

    response.json({
      observationId: String(observation._id),
      inference: aiResponse.data
    });
  } catch (error) {
    if (error.response) {
      return response.status(502).json({
        message: "추론 서버가 오류 응답을 반환했습니다.",
        upstreamStatus: error.response.status
      });
    }

    if (error.code === "ECONNABORTED") {
      return response.status(504).json({ message: "추론 서버 응답 시간이 초과되었습니다." });
    }

    if (error.code === "ECONNREFUSED") {
      return response.status(502).json({ message: "추론 서버에 연결할 수 없습니다." });
    }

    next(error);
  }
});
```

`axios.post()`는 FastAPI의 `/predict`에 POST 요청과 JSON 본문을 보냅니다. `await`는 응답을 기다리는 동안 Node.js의 이벤트 루프가 다른 요청을 처리할 수 있게 합니다. `timeout`은 응답이 무한정 기다려지는 상황을 제한합니다.

예제의 이미지 URL 생성에는 Node.js 백엔드 주소를 사용했습니다. 실제 서비스에서는 공개 가능한 이미지 URL이나 백엔드가 관리하는 인증된 파일 주소 등, 추론 서버가 접근할 수 있는 주소를 사용해야 합니다.

## 7. 서버 간 통신의 오류 처리

Node.js API는 FastAPI와 통신하는 중 다양한 오류를 만날 수 있습니다.

- FastAPI가 실행 중이 아니거나 주소가 잘못된 경우
- FastAPI가 오류 상태 코드와 본문을 반환한 경우
- 추론 서버 응답이 정해진 시간보다 오래 걸리는 경우
- 요청 JSON이나 응답 JSON의 규격이 맞지 않는 경우
- 관측 데이터나 이미지 경로가 존재하지 않는 경우

서버 간 통신 오류를 사용자에게 그대로 노출하기보다, Node.js가 요청 실패를 구분해 `502 Bad Gateway`, `504 Gateway Timeout` 등 알맞은 상태 코드와 메시지를 반환하도록 합니다. 내부 오류 상세 정보는 서버 로그에서 확인하고, 응답에는 민감한 경로나 접속 정보가 포함되지 않도록 합니다.

## 8. PyTorch 모델과 API의 연결 지점

오늘 만든 `/predict`는 임시 예측 결과를 반환합니다. 다음 수업에서는 이 함수 내부에서 PyTorch 모델을 불러와 실제 이미지 추론을 수행하도록 바꿉니다.

```text
현재:
요청 JSON → FastAPI → 예제 결과 JSON

다음 단계:
이미지 입력 → FastAPI → PyTorch 모델 → 예측 결과 JSON
```

모델 파일을 요청마다 다시 읽으면 불필요한 시간이 걸립니다. 실제 서비스에서는 서버 시작 시 모델을 불러와 메모리에 준비하고, 요청이 들어오면 준비된 모델을 사용합니다. 또한 모델의 입력 크기, 전처리 방식, 클래스 이름, 출력 해석 규칙이 학습 과정과 일치해야 합니다.

오늘은 PyTorch 모델 추론 코드를 만들기보다, 추론 서버의 입출력 규격과 Node.js 연동을 완성합니다. 그러면 다음 수업에서 모델을 연결할 위치가 명확해집니다.

## 9. 전체 통신 흐름 확인하기

요청을 처리하는 흐름을 정리합니다.

1. 웹 화면이나 API 클라이언트가 Node.js 서버에 추론을 요청합니다.
2. Node.js는 관측 데이터를 MongoDB에서 조회합니다.
3. Node.js는 관측 ID와 이미지 주소를 JSON으로 FastAPI에 보냅니다.
4. FastAPI는 요청 자료형을 확인하고 추론 결과 JSON을 반환합니다.
5. Node.js는 결과를 웹 화면이나 요청 클라이언트에 전달합니다.

각 서버는 HTTP 상태 코드와 JSON 규격을 지킵니다. 장애가 생기면 어느 구간에서 실패했는지 상태 코드와 로그를 이용해 확인합니다.

## 핵심 정리

- 추론은 학습된 모델을 사용해 입력 데이터의 예측 결과를 계산하는 과정입니다.
- 모델 서빙은 추론 기능을 API로 제공해 다른 프로그램이 이용할 수 있도록 하는 것입니다.
- FastAPI는 Python에서 요청 자료형을 확인하고 HTTP API를 만들 수 있게 합니다.

- `async`와 `await`는 네트워크 응답을 기다리는 동안 이벤트 루프가 다른 작업을 처리하도록 돕습니다.
- Postman은 API의 요청과 응답을 독립적으로 확인하는 데 사용할 수 있습니다.
