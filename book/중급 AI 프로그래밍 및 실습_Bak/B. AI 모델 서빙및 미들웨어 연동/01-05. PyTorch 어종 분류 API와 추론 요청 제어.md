

## 들어가며

앞 장에서는 FastAPI 추론 서버와 Node.js 백엔드가 HTTP와 JSON으로 통신하도록 연결했습니다. 당시 FastAPI는 통신 흐름을 확인하기 위해 예제 예측 결과를 반환했습니다.

이번 장에서는 예제 결과 대신 **PyTorch 어종 분류 모델**을 사용합니다. FastAPI가 이미지를 입력받아 전처리하고 모델 추론을 수행한 뒤, 어종과 신뢰도를 JSON으로 반환하도록 만듭니다. 이어서 Node.js 미들웨어를 사용해 잘못된 요청이나 과도한 추론 요청을 제어합니다.

## 1. 오늘의 요청 처리 흐름

```text
클라이언트
   ↓ 이미지와 관측 ID
Node.js API
   ↓ 인증·요청 검증·요청 빈도 제어
Node.js 미들웨어
   ↓ HTTP + JSON
FastAPI 추론 엔드포인트
   ↓ 이미지 전처리
PyTorch 어종 분류 모델
   ↓ 어종별 점수
FastAPI → Node.js → 클라이언트
```

Node.js는 웹 서비스 요청을 검증하고 AI 서버 호출을 제어합니다. FastAPI는 이미지 입력을 모델에 맞게 변환하고 PyTorch 모델을 실행합니다. 모델의 결과는 JSON 응답 규격에 맞춰 전달합니다.

## 2. 분류 모델 입력과 출력 이해하기

이미지 분류 모델은 이미지를 입력받아 미리 정한 여러 클래스 중 하나 또는 여러 개의 점수를 출력합니다. 예를 들어 클래스가 `참돔`, `광어`, `방어`라면 모델 출력의 각 원소는 클래스별 점수입니다.

```text
입력 이미지
  ↓ 크기 조정, 색상 및 픽셀 정규화
PyTorch 모델
  ↓ logits: [-0.4, 2.1, 0.3]
softmax 확률
  ↓ [0.06, 0.78, 0.16]
예측 결과: 광어, 신뢰도 0.78
```

모델의 원시 출력값을 logits라고 합니다. Softmax는 logits를 클래스별 확률처럼 해석할 수 있는 값으로 변환합니다. 가장 높은 점수의 위치를 클래스 목록과 연결하면 예측 어종을 알 수 있습니다.

모델을 사용할 때는 다음 사항이 학습 당시 설정과 같아야 합니다.

- 입력 이미지의 크기
- RGB 또는 다른 색상 채널 순서
- 픽셀 값의 스케일 및 정규화 방법
- 클래스 이름의 순서
- 모델 출력이 logits인지 이미 확률로 변환된 값인지

## 3. 모델 파일과 클래스 목록 준비하기

이번 예제는 TorchScript 형식의 모델 파일이 준비되어 있다고 가정합니다.

```text
ai_server/
├─ main.py
└─ models/
   ├─ fish_classifier.ts
   └─ classes.json
```

`classes.json`은 모델 출력 인덱스와 어종 이름의 순서를 보관합니다.

```json
[
  "참돔",
  "광어",
  "방어"
]
```

모델이 다른 클래스 순서로 학습됐다면 이 파일도 반드시 그 순서에 맞춰야 합니다. 모델을 만들 때 사용한 전처리 방식과 분류 클래스 목록을 함께 보관하는 것이 좋습니다.

TorchScript가 아닌 `state_dict` 파일을 받았다면 모델 구조를 정의한 뒤 `load_state_dict()`로 가중치를 불러와야 합니다. 가중치 파일만으로는 모델 구조를 알 수 없으므로, 학습 코드나 모델 정의와 전처리 정보를 함께 확인해야 합니다.

## 4. FastAPI에서 PyTorch 모델 불러오기

FastAPI 서버에 필요한 패키지를 설치합니다. PyTorch 설치 방법은 운영체제와 CPU·GPU 환경에 맞는 배포판을 사용합니다.

```bash
python -m pip install fastapi uvicorn torch pillow
```

`ai_server/main.py`에서 모델을 불러오고 입력 이미지를 준비하는 코드를 작성합니다.

```python
import json
from pathlib import Path

import torch
from fastapi import FastAPI, HTTPException
from PIL import Image, ImageOps
from pydantic import BaseModel

BASE_DIR = Path(__file__).resolve().parent
MODEL_PATH = BASE_DIR / "models" / "fish_classifier.ts"
CLASSES_PATH = BASE_DIR / "models" / "classes.json"
IMAGE_SIZE = 224

app = FastAPI(title="Fish Classification API")

if not MODEL_PATH.exists():
    raise RuntimeError(f"모델 파일을 찾을 수 없습니다: {MODEL_PATH}")
if not CLASSES_PATH.exists():
    raise RuntimeError(f"클래스 파일을 찾을 수 없습니다: {CLASSES_PATH}")

with CLASSES_PATH.open("r", encoding="utf-8") as file:
    CLASS_NAMES = json.load(file)

DEVICE = torch.device("cuda" if torch.cuda.is_available() else "cpu")
MODEL = torch.jit.load(str(MODEL_PATH), map_location=DEVICE)
MODEL.eval()


class PredictionRequest(BaseModel):
    observationId: str
    imageBase64: str


class PredictionItem(BaseModel):
    label: str
    confidence: float


class PredictionResponse(BaseModel):
    observationId: str
    predictions: list[PredictionItem]
    modelVersion: str


def decode_image(image_base64: str) -> Image.Image:
    import base64
    from io import BytesIO

    try:
        image_bytes = base64.b64decode(image_base64, validate=True)
        image = Image.open(BytesIO(image_bytes)).convert("RGB")
        return ImageOps.fit(image, (IMAGE_SIZE, IMAGE_SIZE))
    except Exception as error:
        raise ValueError("이미지 Base64 데이터가 올바르지 않습니다.") from error


def image_to_tensor(image: Image.Image) -> torch.Tensor:
    import numpy as np

    array = np.asarray(image, dtype="float32") / 255.0
    mean = np.array([0.485, 0.456, 0.406], dtype="float32")
    std = np.array([0.229, 0.224, 0.225], dtype="float32")
    array = (array - mean) / std
    tensor = torch.from_numpy(array).permute(2, 0, 1).unsqueeze(0)
    return tensor.to(DEVICE)
```

이 예제는 이미지 크기를 `224 × 224`로 맞추고, RGB 채널을 ImageNet 평균과 표준편차 기준으로 정규화합니다. 이는 예시 전처리이며, 실제 모델이 학습될 때 사용한 전처리와 반드시 일치시켜야 합니다. 다르게 학습한 모델이라면 크기, 평균·표준편차, 자르기 방법을 학습 설정에 맞게 수정합니다.

`MODEL.eval()`은 모델을 추론 모드로 전환합니다. GPU가 사용 가능하면 GPU를 선택하고, 그렇지 않으면 CPU를 사용합니다. 모델은 서버 시작 시 한 번 불러와 메모리에 준비합니다.

## 5. FastAPI 추론 엔드포인트 만들기

이미지 전처리 함수 아래에 `/predict` 엔드포인트를 추가합니다.

```python
@app.get("/health")
def health_check():
    return {
        "status": "ok",
        "device": str(DEVICE),
        "modelVersion": "fish-classifier-v1"
    }


@app.post("/predict", response_model=PredictionResponse)
def predict(request: PredictionRequest):
    try:
        image = decode_image(request.imageBase64)
    except ValueError as error:
        raise HTTPException(status_code=400, detail=str(error)) from error

    input_tensor = image_to_tensor(image)

    try:
        with torch.inference_mode():
            logits = MODEL(input_tensor)
            probabilities = torch.softmax(logits, dim=1)[0]
            top_count = min(3, len(CLASS_NAMES))
            scores, indices = torch.topk(probabilities, k=top_count)
    except Exception as error:
        raise HTTPException(status_code=500, detail="모델 추론에 실패했습니다.") from error

    predictions = [
        PredictionItem(
            label=CLASS_NAMES[index],
            confidence=round(float(score), 4)
        )
        for score, index in zip(scores.cpu().tolist(), indices.cpu().tolist())
    ]

    return PredictionResponse(
        observationId=request.observationId,
        predictions=predictions,
        modelVersion="fish-classifier-v1"
    )
```

`torch.inference_mode()`는 추론에 필요하지 않은 학습용 계산을 줄입니다. `torch.softmax()`는 모델 출력값을 확률로 바꾸고, `torch.topk()`는 점수가 높은 결과를 선택합니다. 결과는 클래스 이름과 점수를 묶어 응답합니다.

서버를 실행합니다.

```bash
python -m uvicorn ai_server.main:app --reload --host 127.0.0.1 --port 8000
```

`GET /health`로 모델 서버가 실행 중인지 확인합니다. 모델 파일 또는 클래스 파일 경로가 맞지 않으면 서버가 시작되지 않으므로 오류 메시지를 확인합니다.

## 6. Node.js에서 이미지 데이터를 전달하기

예제에서는 클라이언트가 이미지를 Base64 문자열로 Node.js에 보내고, Node.js가 같은 JSON을 FastAPI로 전달합니다. Base64는 텍스트로 이진 이미지 데이터를 표현하는 방식이며 원본보다 전송 크기가 커집니다. 대용량 이미지에는 multipart 업로드나 파일 저장소를 사용하는 것이 더 적절합니다.

Node.js 프로젝트에 요청 크기 제한을 설정합니다.

```javascript
app.use(express.json({ limit: "8mb" }));
```

요청 본문이 과도하게 커지지 않도록 제한을 둡니다. 이 제한은 Base64 변환 후 크기를 고려해 정해야 합니다.

요청 본문 예시:

```json
{
  "observationId": "obs-001",
  "imageBase64": "iVBORw0KGgoAAAANSUhEUg..."
}
```

## 7. Node.js 미들웨어로 추론 요청 제어하기

미들웨어는 라우트 처리 전후에 실행되어 공통 작업을 수행합니다. 인증 확인, 입력 검증, 로그 기록, 요청 빈도 제한 등을 미들웨어로 구성할 수 있습니다.

먼저 요청 빈도 제한 패키지를 설치합니다.

```bash
npm install express-rate-limit
```

`server.js`에서 제한 미들웨어와 동시 요청 수 제한 미들웨어를 정의합니다.

```javascript
const { rateLimit } = require("express-rate-limit");

const inferenceRateLimit = rateLimit({
  windowMs: 60 * 1000,
  limit: 10,
  standardHeaders: "draft-8",
  legacyHeaders: false,
  message: { message: "추론 요청 횟수가 많습니다. 잠시 후 다시 요청하세요." }
});

let activeInferenceCount = 0;
const MAX_ACTIVE_INFERENCES = 2;

function validateInferenceRequest(request, response, next) {
  const { observationId, imageBase64 } = request.body ?? {};

  if (typeof observationId !== "string" || observationId.trim() === "") {
    return response.status(400).json({ message: "observationId가 필요합니다." });
  }

  if (typeof imageBase64 !== "string" || imageBase64.length === 0) {
    return response.status(400).json({ message: "imageBase64가 필요합니다." });
  }

  if (imageBase64.length > 7_000_000) {
    return response.status(413).json({ message: "이미지 크기가 제한을 초과했습니다." });
  }

  next();
}

function limitConcurrentInference(request, response, next) {
  if (activeInferenceCount >= MAX_ACTIVE_INFERENCES) {
    response.set("Retry-After", "2");
    return response.status(503).json({
      message: "현재 추론 요청이 많습니다. 잠시 후 다시 시도하세요."
    });
  }

  activeInferenceCount += 1;
  let released = false;

  function releaseSlot() {
    if (released) return;
    released = true;
    activeInferenceCount -= 1;
  }

  response.once("finish", releaseSlot);
  response.once("close", releaseSlot);
  next();
}
```

`inferenceRateLimit`은 한 IP에서 1분 동안 보낼 수 있는 요청 수를 제한합니다. `validateInferenceRequest`는 필수 필드와 이미지 데이터 크기를 확인합니다. `limitConcurrentInference`는 동시에 처리하는 추론 요청 수를 제한하고, 용량을 넘으면 `503 Service Unavailable`과 재시도 안내를 반환합니다.

동시 요청 수는 서버의 CPU·GPU 메모리와 모델 처리 속도에 맞춰 조정해야 합니다. 여러 Node.js 프로세스나 서버를 사용하는 환경에서는 메모리 변수만으로 전체 요청 수를 제한할 수 없으므로 Redis 같은 공용 저장소나 별도의 작업 큐가 필요할 수 있습니다.

## 8. Node.js에서 FastAPI 호출하기

Axios로 FastAPI에 요청을 전달하는 라우트를 추가합니다.

```javascript
const axios = require("axios");

app.post(
  "/api/inference/predict",
  inferenceRateLimit,
  validateInferenceRequest,
  limitConcurrentInference,
  async (request, response, next) => {
    try {
      const aiResponse = await axios.post(
        `${process.env.AI_SERVER_URL}/predict`,
        {
          observationId: request.body.observationId,
          imageBase64: request.body.imageBase64
        },
        { timeout: 30000 }
      );

      response.json(aiResponse.data);
    } catch (error) {
      if (error.response) {
        return response.status(502).json({
          message: "추론 서버가 요청을 처리하지 못했습니다.",
          upstreamStatus: error.response.status
        });
      }

      if (error.code === "ECONNABORTED") {
        return response.status(504).json({ message: "추론 처리 시간이 초과되었습니다." });
      }

      if (error.code === "ECONNREFUSED") {
        return response.status(502).json({ message: "추론 서버에 연결할 수 없습니다." });
      }

      next(error);
    }
  }
);
```

미들웨어는 등록한 순서대로 실행됩니다. 먼저 요청 빈도를 확인하고, 다음으로 입력을 검사하고, 추론 동시 처리 용량을 확보한 뒤 FastAPI를 호출합니다. 요청이 종료되면 확보한 처리 슬롯을 반환합니다.

## 9. Postman으로 전체 요청 테스트하기

Node.js 서버와 FastAPI 서버를 각각 실행합니다. Postman에서 Node.js API로 POST 요청을 보냅니다.

- Method: `POST`
- URL: `http://localhost:3000/api/inference/predict`
- Body: `raw` → `JSON`

Base64 이미지 문자열을 포함한 JSON을 보냅니다.

```json
{
  "observationId": "obs-001",
  "imageBase64": "실제 이미지 파일을 Base64로 인코딩한 값"
}
```

정상 응답에서는 관측 ID, 상위 예측 결과, 모델 버전을 확인합니다.

```json
{
  "observationId": "obs-001",
  "predictions": [
    { "label": "광어", "confidence": 0.7812 },
    { "label": "참돔", "confidence": 0.1431 },
    { "label": "방어", "confidence": 0.0757 }
  ],
  "modelVersion": "fish-classifier-v1"
}
```

다음 상황도 테스트합니다.

- `observationId`를 보내지 않으면 `400`이 반환되는가?
- 이미지 문자열을 보내지 않으면 `400`이 반환되는가?
- 크기 제한을 넘으면 `413`이 반환되는가?
- FastAPI를 중지한 뒤 호출하면 `502`가 반환되는가?
- 1분 내 허용 요청 수를 넘으면 요청 빈도 제한 응답이 오는가?

## 10. 추론 결과 해석 시 주의할 점

분류 모델의 confidence는 모델이 해당 클래스에 부여한 점수입니다. 모델이 높은 confidence를 반환했다고 해서 결과가 항상 정답이라는 뜻은 아닙니다. 학습 데이터와 촬영 환경이 다르거나, 이미지가 흐리거나, 분류 대상이 학습 클래스에 없는 경우에도 높은 점수가 나올 수 있습니다.

서비스에서는 모델 버전과 입력 관측 ID를 함께 기록하고, 필요한 경우 낮은 신뢰도 결과를 사람이 확인하도록 설계할 수 있습니다. 여러 클래스의 점수와 신뢰도 임계값을 저장하면 이후 오분류 검토와 재학습에 활용할 수 있습니다.

## 핵심 정리

- PyTorch 모델의 추론에는 학습 때와 일치하는 이미지 전처리와 클래스 순서가 필요합니다.
- FastAPI는 입력 이미지를 검증하고 모델 추론 결과를 JSON으로 반환할 수 있습니다.
- Softmax와 상위 점수 선택을 이용해 예측 어종과 confidence를 구성할 수 있습니다.
- Node.js 미들웨어는 요청 검증, 빈도 제한, 동시 처리 수 제어 등 공통 정책을 적용합니다.
- Axios의 timeout과 HTTP 오류 처리를 통해 FastAPI 장애를 Node.js 응답으로 전달할 수 있습니다.
- Postman으로 API의 정상·오류·제한 동작을 독립적으로 확인할 수 있습니다.
- 다음 수업에서는 추론 결과 데이터 전송 규격을 최적화합니다.
