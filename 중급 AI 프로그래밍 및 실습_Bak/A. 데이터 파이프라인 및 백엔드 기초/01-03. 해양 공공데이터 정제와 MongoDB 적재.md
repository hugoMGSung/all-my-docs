

## 들어가며

앞 장에서는 수산물 관측 데이터를 저장하고 조회하는 API를 만들었습니다. 이번 장에서는 해양 공공데이터를 서비스에 사용할 수 있는 형태로 정리하고 MongoDB에 적재하는 **데이터 파이프라인**을 만듭니다.

공공데이터는 출처에 따라 필드 이름, 날짜 형식, 숫자 표현, 결측값 표기가 다를 수 있습니다. 따라서 원본을 그대로 저장하기보다 필요한 항목을 골라 값과 형식을 정리하고, 유효성을 확인한 뒤 저장해야 합니다.

오늘은 CSV 파일을 입력으로 사용합니다. 실제 공공데이터의 내려받기 형식이 JSON이나 다른 CSV여도, 입력을 정규화한 뒤 저장한다는 전체 과정은 같습니다.

## 1. 데이터 파이프라인이란?

데이터 파이프라인은 데이터를 가져와 필요한 변환을 수행하고, 목적지에 저장하는 일련의 과정입니다.

```text
공공데이터 원본
      ↓
읽기 (Extract)
      ↓
정제·변환 (Transform)
      ↓
검증
      ↓
MongoDB 적재 (Load)
```

이 흐름은 ETL이라고도 합니다. Extract는 데이터를 가져오는 단계, Transform은 분석과 서비스에 맞게 정리하는 단계, Load는 데이터베이스나 저장소에 넣는 단계입니다.

데이터를 정제하면 다음 문제를 줄일 수 있습니다.

- 같은 의미의 필드가 서로 다른 이름으로 들어오는 문제
- 날짜와 숫자가 문자열로 저장되는 문제
- 빈 값이나 잘못된 값이 분석 결과에 영향을 주는 문제
- 같은 파일을 다시 적재했을 때 중복 문서가 쌓이는 문제

## 2. 원본 데이터와 서비스 데이터 구분하기

공공데이터의 원본 필드 이름이 서비스에서 사용하기 편한 이름과 다를 수 있습니다. 원본 형식을 서비스 데이터 형식으로 변환하는 매핑 규칙을 정합니다.

| 원본 CSV 필드 | 서비스 필드 | 정제 규칙 |
|---|---|---|
| `관측소코드` | `stationId` | 문자열로 저장하고 공백 제거 |
| `관측일시` | `observedAt` | 날짜 객체로 변환 |
| `수온(℃)` | `waterTemperature` | 숫자로 변환 |
| `염분(PSU)` | `salinity` | 숫자로 변환, 결측이면 `null` |
| `위도` | `location.latitude` | 숫자로 변환하고 범위 확인 |
| `경도` | `location.longitude` | 숫자로 변환하고 범위 확인 |
| `어종` | `species` | 공백 제거, 빈 값은 `null` |

이 표를 데이터 사전으로 사용할 수 있습니다. 어떤 값이 필수이고, 단위와 자료형이 무엇인지 미리 정하면 여러 출처의 데이터를 같은 형태로 처리하기 쉽습니다.

## 3. MongoDB에 저장할 문서 설계

정제한 해양 관측 자료는 다음과 같은 문서로 저장하겠습니다.

```json
{
  "source": "public-marine-data",
  "externalId": "station-032_2026-12-01T09:00:00Z",
  "stationId": "station-032",
  "observedAt": "2026-12-01T09:00:00.000Z",
  "waterTemperature": 18.7,
  "salinity": 32.1,
  "species": "참돔",
  "location": {
    "latitude": 35.12,
    "longitude": 129.04
  },
  "imageUrl": null,
  "importedAt": "2026-12-01T10:00:00.000Z"
}
```

`externalId`는 원본 데이터에서 관측 행을 구별하기 위해 만드는 식별자입니다. 원본에 고유한 자료 ID가 있다면 그 ID를 사용합니다. 고유 ID가 없다면 관측소 ID와 관측 시각을 조합하는 등 중복을 판별할 규칙을 정합니다.

`source`는 데이터가 어느 출처에서 왔는지 기록합니다. 이후 다른 기관의 자료가 추가되어도 데이터 출처를 구분할 수 있습니다. `imageUrl`처럼 관측 데이터에 없을 수 있는 정보는 `null`로 저장할 수 있습니다.

## 4. 실습용 CSV 준비하기

프로젝트 폴더에 `data/marine-observations.csv` 파일을 만듭니다. 아래 첫 줄은 열 이름이며, 이어지는 줄이 각 관측 기록입니다.

```csv
관측소코드,관측일시,수온(℃),염분(PSU),위도,경도,어종
station-032,2026-12-01 09:00,18.7,32.1,35.12,129.04,참돔
station-032,2026-12-01 10:00,19.1,32.0,35.12,129.04,참돔
station-041,2026-12-01 09:00,NA,31.8,34.88,128.76,
station-050,날짜오류,21.4,33.0,95.2,129.10,방어
```

예제에는 정상 자료와 함께 결측 수온·어종, 잘못된 날짜, 위도 범위를 벗어난 값도 넣었습니다. 파이프라인이 잘못된 자료를 식별하고 적절히 처리하는지 확인하기 위해서입니다.

실제 수업에서는 담당자가 제공한 해양 공공데이터 파일을 사용하고, 파일의 실제 열 이름에 맞게 매핑 규칙을 수정합니다. 실습용 자료를 사용할 때에도 원본 파일은 보존하고 정제된 결과를 별도로 만듭니다.

## 5. CSV 파일 읽기

CSV를 쉽게 처리하기 위해 파서를 설치합니다.

```bash
npm install csv-parse
```

프로젝트에 `scripts/import-marine-data.js` 파일을 만들고 CSV를 읽는 코드를 작성합니다.

```javascript
require("dotenv").config();

const fs = require("node:fs");
const path = require("node:path");
const { parse } = require("csv-parse/sync");
const { connectToDatabase, getDatabase } = require("../db");

function readCsv(filePath) {
  const csvText = fs.readFileSync(filePath, "utf8");

  return parse(csvText, {
    columns: true,
    skip_empty_lines: true,
    bom: true,
    trim: true
  });
}
```

`columns: true`를 지정하면 첫 줄의 열 이름을 각 행의 속성명으로 사용합니다. `trim: true`는 셀 앞뒤의 불필요한 공백을 제거합니다. `bom: true`는 일부 스프레드시트 프로그램에서 저장한 CSV의 BOM(Byte Order Mark)을 처리합니다.

실제 파일에 쉼표가 포함된 값이 있다면 CSV 규칙에 맞게 따옴표로 감싸야 합니다. CSV 파서를 사용하면 따옴표 안에 들어간 쉼표도 하나의 값으로 처리할 수 있습니다.

## 6. 값 정제와 검증

원본 CSV의 값은 대부분 문자열로 읽힙니다. 숫자, 날짜, 빈 값의 규칙을 정해 변환해야 합니다.

```javascript
function parseOptionalNumber(value) {
  if (value === undefined || value === null) {
    return null;
  }

  const normalized = String(value).trim();
  if (normalized === "" || normalized === "NA" || normalized === "N/A" || normalized === "-") {
    return null;
  }

  const number = Number(normalized);
  return Number.isFinite(number) ? number : null;
}

function parseDate(value) {
  const date = new Date(value);
  return Number.isNaN(date.getTime()) ? null : date;
}

function cleanRow(row, lineNumber) {
  const stationId = String(row["관측소코드"] ?? "").trim();
  const observedAt = parseDate(row["관측일시"]);
  const waterTemperature = parseOptionalNumber(row["수온(℃)"]);
  const salinity = parseOptionalNumber(row["염분(PSU)"]);
  const latitude = parseOptionalNumber(row["위도"]);
  const longitude = parseOptionalNumber(row["경도"]);
  const species = String(row["어종"] ?? "").trim() || null;

  const errors = [];

  if (!stationId) errors.push("관측소코드 누락");
  if (!observedAt) errors.push("관측일시가 없거나 올바르지 않음");
  if (waterTemperature === null) errors.push("수온이 없거나 숫자가 아님");
  if (latitude !== null && (latitude < -90 || latitude > 90)) {
    errors.push("위도 범위 오류");
  }
  if (longitude !== null && (longitude < -180 || longitude > 180)) {
    errors.push("경도 범위 오류");
  }

  if (errors.length > 0) {
    return {
      ok: false,
      lineNumber,
      errors,
      original: row
    };
  }

  const externalId = `${stationId}_${observedAt.toISOString()}`;

  return {
    ok: true,
    document: {
      source: "public-marine-data",
      externalId,
      stationId,
      observedAt,
      waterTemperature,
      salinity,
      species,
      location: {
        latitude,
        longitude
      },
      imageUrl: null,
      importedAt: new Date()
    }
  };
}
```

`parseOptionalNumber()`는 정상 숫자를 숫자 자료형으로 바꾸고, 결측값이나 숫자로 해석할 수 없는 값은 `null`로 처리합니다. 필수 수온 값이 없으면 해당 행은 적재하지 않도록 검증합니다. 위도와 경도는 값이 있을 때 허용 범위에 있는지 확인합니다.

위 예제에서는 잘못된 행을 데이터베이스에 넣는 대신 오류 목록에 기록합니다. 실제 운영에서는 데이터 성격에 따라 결측 행을 버릴지, 보완할지, `null`로 저장할지 정책을 정해야 합니다. 결측과 0은 의미가 다르므로 결측값을 무조건 0으로 바꾸면 안 됩니다.

날짜 입력 형식이 여러 가지라면 제공기관의 명세를 확인해 허용 형식을 명시적으로 처리합니다. 시간대 정보가 없는 날짜는 서버의 시간대 설정에 영향을 받을 수 있으므로, 가능하면 원본 시간대나 UTC 변환 규칙을 정해 둡니다.

## 7. 정제 결과를 MongoDB에 적재하기

같은 파일을 다시 실행해도 같은 관측 자료가 중복으로 쌓이지 않도록 `externalId` 기준으로 upsert합니다. upsert는 조건에 맞는 문서가 있으면 갱신하고, 없으면 새 문서를 추가하는 작업입니다.

앞에서 만든 파일에 다음 코드를 이어 붙입니다.

```javascript
async function importFile(filePath) {
  const rows = readCsv(filePath);
  const accepted = [];
  const rejected = [];

  rows.forEach((row, index) => {
    const result = cleanRow(row, index + 2);

    if (result.ok) {
      accepted.push(result.document);
    } else {
      rejected.push(result);
    }
  });

  await connectToDatabase();
  const db = getDatabase();
  const collection = db.collection("marineObservations");

  if (accepted.length > 0) {
    const operations = accepted.map((document) => ({
      updateOne: {
        filter: { externalId: document.externalId },
        update: {
          $set: document,
          $setOnInsert: { firstImportedAt: new Date() }
        },
        upsert: true
      }
    }));

    const result = await collection.bulkWrite(operations, { ordered: false });

    console.log(`입력 행: ${rows.length}`);
    console.log(`검증 통과 행: ${accepted.length}`);
    console.log(`새 문서: ${result.upsertedCount}`);
    console.log(`기존 문서 갱신: ${result.modifiedCount}`);
  } else {
    console.log(`입력 행: ${rows.length}`);
    console.log("적재할 유효 데이터가 없습니다.");
  }

  console.log(`제외 행: ${rejected.length}`);
  for (const item of rejected) {
    console.log(`CSV ${item.lineNumber}행 제외: ${item.errors.join(", ")}`);
  }
}

const inputPath = process.argv[2]
  ? path.resolve(process.argv[2])
  : path.join(__dirname, "..", "data", "marine-observations.csv");

importFile(inputPath)
  .then(() => process.exit(0))
  .catch((error) => {
    console.error("데이터 적재에 실패했습니다.", error);
    process.exit(1);
  });
```

`bulkWrite()`는 여러 건의 쓰기 작업을 묶어 데이터베이스 요청 횟수를 줄입니다. `ordered: false`는 특정 작업이 실패하더라도 가능한 나머지 작업을 계속 시도하도록 합니다. 적재 결과에서 새 문서와 갱신된 문서의 수를 확인합니다.

`$set`은 문서의 정제 데이터를 저장하고, `$setOnInsert`는 새 문서가 만들어질 때만 최초 적재 시각을 기록합니다. 재실행 시에도 `externalId`가 같으면 중복 문서를 만들지 않습니다.

파일을 지정하지 않고 실행하면 기본 CSV 파일을 읽습니다.

```bash
node scripts/import-marine-data.js
```

다른 CSV 파일을 지정할 수도 있습니다.

```bash
node scripts/import-marine-data.js ./data/another-marine-data.csv
```

## 8. 적재한 데이터 확인하기

MongoDB에서 데이터베이스와 컬렉션을 선택하고 문서를 조회합니다.

```javascript
use smart_aquaculture

db.marineObservations.find().sort({ observedAt: -1 })
```

문서 개수도 확인합니다.

```javascript
db.marineObservations.countDocuments()
```

관측소 하나의 자료만 조회할 수 있습니다.

```javascript
db.marineObservations.find({ stationId: "station-032" })
```

같은 CSV를 다시 실행해도 문서 개수가 계속 늘어나지 않는지 확인합니다. 원본 파일에서 값을 수정한 뒤 다시 적재하면 해당 `externalId` 문서가 갱신되는지도 살펴봅니다.

## 9. 정제·적재 작업에서 기록할 정보

데이터를 적재할 때는 성공 여부뿐 아니라 어떤 자료가 어떻게 처리됐는지도 남기는 것이 좋습니다.

- 입력 파일 이름과 데이터 출처
- 전체 입력 행 수
- 검증을 통과한 행 수
- 새로 추가하거나 갱신한 문서 수
- 제외한 행 번호와 제외 사유
- 적재를 실행한 시각

이 정보가 있으면 데이터가 예상보다 적게 들어왔을 때 원인을 찾을 수 있습니다. 대량 자료를 처리할 때는 오류 행을 별도 파일로 저장하거나 import 이력을 컬렉션으로 관리할 수도 있습니다.

## 실습: 해양 관측 데이터 적재 프로젝트

제공된 해양 공공데이터 파일을 사용해 다음 파이프라인을 완성합니다.

- 원본 필드와 MongoDB 문서 필드의 매핑 표를 작성합니다.
- 날짜·숫자·결측값을 정제합니다.
- 필수 항목과 위도·경도 범위를 검증합니다.
- 유효한 행만 MongoDB `marineObservations` 컬렉션에 적재합니다.
- `externalId`를 기준으로 중복 없이 재실행할 수 있게 합니다.
- 입력·통과·제외·추가·갱신 건수를 출력합니다.
- 제외된 각 행의 번호와 이유를 확인합니다.

## 오늘의 미션

- ETL의 세 단계와 오늘의 데이터 흐름을 설명합니다.
- 원본 필드와 서비스 필드 사이의 매핑 규칙을 정합니다.
- 문자열로 읽은 날짜와 숫자를 적절한 자료형으로 변환합니다.
- 결측값과 잘못된 값을 구별하고 정해 둔 기준으로 처리합니다.
- MongoDB에 해양 관측 문서를 적재합니다.
- 같은 데이터를 다시 적재해도 중복이 생기지 않는지 확인합니다.

## 핵심 정리

- 데이터 파이프라인은 데이터를 읽고, 정제·변환하고, 저장하는 흐름입니다.
- 공공데이터 원본과 서비스 데이터 사이에 필드 매핑 규칙이 필요합니다.
- 날짜·숫자·결측값의 자료형과 처리 정책을 명확히 해야 합니다.
- 유효하지 않은 데이터는 저장 전에 검증하고 제외 사유를 기록할 수 있습니다.
- `bulkWrite()`와 `upsert`를 사용하면 여러 건을 효율적으로 적재하고 재실행 시 중복을 줄일 수 있습니다.
- 다음 수업에서는 AI 모델의 추론을 API로 제공하는 서버를 살펴봅니다.
