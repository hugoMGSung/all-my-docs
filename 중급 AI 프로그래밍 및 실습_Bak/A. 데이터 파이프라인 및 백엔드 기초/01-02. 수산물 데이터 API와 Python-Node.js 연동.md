

## 들어가며

앞 장에서는 REST API의 구조를 살펴보고 Express로 첫 서버를 만들었습니다. 이번 장에서는 서버를 실제 데이터베이스와 연결해 **수산물 관측 데이터를 등록하고 조회하는 API**를 만듭니다. 이어서 Node.js 서버가 Python 프로그램을 자식 프로세스로 실행하고 결과를 전달받는 방법을 실습합니다.

오늘의 목표는 다음 두 가지입니다.

- Express API 서버와 MongoDB를 연결해 수산물 데이터를 관리합니다.
- Node.js에서 Python 스크립트를 실행하고 입력과 결과를 주고받습니다.

## 1. 오늘 만들 기능

오늘은 1일차의 스마트 양식장 API 서버를 확장합니다. 관측 데이터는 양식장, 관측 시각, 수온, 이미지 경로 등의 정보를 가질 수 있습니다.

오늘 구현할 API는 다음과 같습니다.

| 작업 | HTTP 메서드 | 주소 | 설명 |
|---|---|---|---|
| 관측 데이터 목록 조회 | `GET` | `/api/observations` | 저장된 관측 데이터 목록을 반환 |
| 관측 데이터 한 건 조회 | `GET` | `/api/observations/:id` | ID로 관측 데이터를 조회 |
| 관측 데이터 등록 | `POST` | `/api/observations` | 새 관측 데이터를 저장 |
| 관측 데이터 수정 | `PATCH` | `/api/observations/:id` | 전달한 필드만 수정 |
| 관측 데이터 삭제 | `DELETE` | `/api/observations/:id` | ID에 해당하는 데이터 삭제 |
| Python 분석 실행 | `POST` | `/api/analysis/summary` | 입력 데이터를 Python 프로그램에 전달하고 결과를 반환 |

## 2. MongoDB에 저장할 문서 구조

MongoDB는 데이터를 컬렉션 안에 JSON과 비슷한 문서 형태로 저장하는 NoSQL 데이터베이스입니다. 관계형 데이터베이스처럼 모든 데이터를 미리 고정된 표 구조에 넣는 대신, 문서 안에 필요한 필드를 구성할 수 있습니다.

관측 데이터 한 건은 다음과 같은 문서로 표현할 수 있습니다.

```json
{
  "pondId": "pond-01",
  "species": "참돔",
  "observedAt": "2026-12-01T09:30:00.000Z",
  "waterTemperature": 24.5,
  "image": {
    "fileName": "obs-001.jpg",
    "contentType": "image/jpeg",
    "url": "/uploads/obs-001.jpg"
  },
  "aiResult": {
    "label": "참돔",
    "confidence": 0.94
  }
}
```

MongoDB가 문서를 저장할 때 `_id`를 자동으로 생성합니다. 애플리케이션은 `_id`를 이용해 특정 관측 데이터를 조회하거나 수정할 수 있습니다.

이미지 파일 자체는 별도의 파일 저장소에 두고, MongoDB 문서에는 파일 이름과 위치를 기록합니다. 오늘의 API는 이미지 업로드 기능까지 구현하지 않으며, 이미지 경로를 문자열로 저장하는 방식으로 데이터 매핑을 연습합니다.

## 3. MongoDB와 프로젝트 준비하기

MongoDB 서버가 실행 중인지 확인합니다. 로컬 MongoDB를 설치해 둔 경우 해당 서비스를 실행하고, MongoDB Atlas를 사용하는 경우 연결 문자열을 준비합니다.

1일차 프로젝트 폴더에서 MongoDB 드라이버와 환경 변수 패키지를 설치합니다.

```bash
npm install mongodb dotenv
```

프로젝트 루트에 `.env` 파일을 만들고 연결 정보와 데이터베이스 이름을 작성합니다.

```text
MONGODB_URI=mongodb://127.0.0.1:27017
DB_NAME=smart_aquaculture
PORT=3000
```

`.env`에는 데이터베이스 접속 정보가 들어갈 수 있습니다. 이 파일은 외부에 공개하거나 Git 저장소에 올리지 않도록 `.gitignore`에 추가합니다.

```text
node_modules/
.env
```

MongoDB Atlas를 사용한다면 실제 연결 문자열을 `MONGODB_URI`에 넣습니다. 비밀번호가 포함된 연결 문자열은 수업 자료나 공개 저장소에 그대로 올리지 않습니다.

## 4. Node.js에서 MongoDB 연결하기

`db.js` 파일을 만들고 MongoDB 연결을 담당하는 코드를 작성합니다.

```javascript
const { MongoClient } = require("mongodb");

const uri = process.env.MONGODB_URI;
const dbName = process.env.DB_NAME;

if (!uri) {
  throw new Error("MONGODB_URI 환경 변수를 설정해야 합니다.");
}

const client = new MongoClient(uri);
let database;

async function connectToDatabase() {
  if (!database) {
    await client.connect();
    database = client.db(dbName);
    console.log(`MongoDB 연결 완료: ${dbName}`);
  }

  return database;
}

function getDatabase() {
  if (!database) {
    throw new Error("데이터베이스에 먼저 연결해야 합니다.");
  }

  return database;
}

module.exports = { connectToDatabase, getDatabase };
```

`MongoClient`는 Node.js 프로그램과 MongoDB 서버 사이의 연결을 관리합니다. `connectToDatabase()`는 서버를 시작할 때 한 번 연결하고, `getDatabase()`는 연결된 데이터베이스 객체를 가져옵니다.

## 5. Express 서버에서 CRUD API 만들기

CRUD는 데이터의 생성(Create), 조회(Read), 수정(Update), 삭제(Delete)를 뜻합니다. 다음 코드를 `server.js`에 작성합니다.

```javascript
require("dotenv").config();

const express = require("express");
const { ObjectId } = require("mongodb");
const { connectToDatabase, getDatabase } = require("./db");

const app = express();
const PORT = Number(process.env.PORT) || 3000;

app.use(express.json());

function isValidObjectId(id) {
  return ObjectId.isValid(id) && String(new ObjectId(id)) === id;
}

app.get("/api/observations", async (request, response, next) => {
  try {
    const db = getDatabase();
    const items = await db
      .collection("observations")
      .find({})
      .sort({ observedAt: -1 })
      .toArray();

    response.json({ items, count: items.length });
  } catch (error) {
    next(error);
  }
});

app.get("/api/observations/:id", async (request, response, next) => {
  try {
    const { id } = request.params;

    if (!isValidObjectId(id)) {
      return response.status(400).json({ message: "올바르지 않은 관측 ID입니다." });
    }

    const db = getDatabase();
    const item = await db.collection("observations").findOne({
      _id: new ObjectId(id)
    });

    if (!item) {
      return response.status(404).json({ message: "관측 데이터를 찾을 수 없습니다." });
    }

    response.json(item);
  } catch (error) {
    next(error);
  }
});

app.post("/api/observations", async (request, response, next) => {
  try {
    const { pondId, species, observedAt, waterTemperature, image } = request.body;

    if (!pondId || !species || !observedAt) {
      return response.status(400).json({
        message: "pondId, species, observedAt은 필수 항목입니다."
      });
    }

    if (typeof waterTemperature !== "number") {
      return response.status(400).json({
        message: "waterTemperature은 숫자여야 합니다."
      });
    }

    const document = {
      pondId,
      species,
      observedAt: new Date(observedAt),
      waterTemperature,
      image: image ?? null,
      createdAt: new Date()
    };

    if (Number.isNaN(document.observedAt.getTime())) {
      return response.status(400).json({ message: "관측 시각 형식이 올바르지 않습니다." });
    }

    const db = getDatabase();
    const result = await db.collection("observations").insertOne(document);
    const created = await db.collection("observations").findOne({
      _id: result.insertedId
    });

    response.status(201).json(created);
  } catch (error) {
    next(error);
  }
});

app.patch("/api/observations/:id", async (request, response, next) => {
  try {
    const { id } = request.params;

    if (!isValidObjectId(id)) {
      return response.status(400).json({ message: "올바르지 않은 관측 ID입니다." });
    }

    const allowedFields = ["pondId", "species", "observedAt", "waterTemperature", "image"];
    const updates = {};

    for (const field of allowedFields) {
      if (request.body[field] !== undefined) {
        updates[field] = request.body[field];
      }
    }

    if (Object.keys(updates).length === 0) {
      return response.status(400).json({ message: "수정할 필드가 없습니다." });
    }

    if (updates.observedAt !== undefined) {
      updates.observedAt = new Date(updates.observedAt);
      if (Number.isNaN(updates.observedAt.getTime())) {
        return response.status(400).json({ message: "관측 시각 형식이 올바르지 않습니다." });
      }
    }

    if (updates.waterTemperature !== undefined && typeof updates.waterTemperature !== "number") {
      return response.status(400).json({ message: "waterTemperature은 숫자여야 합니다." });
    }

    const db = getDatabase();
    const result = await db.collection("observations").findOneAndUpdate(
      { _id: new ObjectId(id) },
      { $set: updates },
      { returnDocument: "after" }
    );

    if (!result) {
      return response.status(404).json({ message: "관측 데이터를 찾을 수 없습니다." });
    }

    response.json(result);
  } catch (error) {
    next(error);
  }
});

app.delete("/api/observations/:id", async (request, response, next) => {
  try {
    const { id } = request.params;

    if (!isValidObjectId(id)) {
      return response.status(400).json({ message: "올바르지 않은 관측 ID입니다." });
    }

    const db = getDatabase();
    const result = await db.collection("observations").deleteOne({
      _id: new ObjectId(id)
    });

    if (result.deletedCount === 0) {
      return response.status(404).json({ message: "관측 데이터를 찾을 수 없습니다." });
    }

    response.status(204).send();
  } catch (error) {
    next(error);
  }
});

app.use((error, request, response, next) => {
  console.error(error);
  response.status(500).json({ message: "서버에서 요청을 처리하지 못했습니다." });
});

async function startServer() {
  await connectToDatabase();
  app.listen(PORT, () => {
    console.log(`서버가 http://localhost:${PORT} 에서 실행 중입니다.`);
  });
}

startServer().catch((error) => {
  console.error("서버를 시작하지 못했습니다.", error);
  process.exit(1);
});
```

`express.json()`은 JSON 요청 본문을 `request.body`에서 사용할 수 있게 합니다. `request.params.id`는 주소에 포함된 ID이고, `insertOne()`, `find()`, `findOne()`, `updateOne()` 계열 메서드, `deleteOne()`은 MongoDB 컬렉션에 데이터를 생성·조회·수정·삭제합니다.

요청 값은 데이터베이스에 저장하기 전에 확인합니다. 잘못된 요청은 `400`, 찾을 수 없는 데이터는 `404`, 새 데이터 생성은 `201`, 삭제 성공은 응답 본문이 없는 `204`로 알립니다.

## 7. Node.js와 Python은 왜 연동할까요?

이 과정의 웹 API와 데이터 관리는 Node.js로 구현하고, AI 모델이나 데이터 처리 코드는 Python으로 작성할 수 있습니다. 기존 Python 코드를 Node.js 서버에서 활용하거나, 데이터 처리 작업을 별도 프로그램으로 나누고 싶을 때 자식 프로세스 연동을 사용할 수 있습니다.

Node.js는 운영체제에 별도의 프로세스를 생성해 Python 프로그램을 실행할 수 있습니다. 부모 프로세스는 Node.js 서버이고, 자식 프로세스는 실행된 Python 프로그램입니다.

```text
Node.js API 서버 (부모 프로세스)
        │ 입력 데이터 전달
        ↓
Python 분석 프로그램 (자식 프로세스)
        │ 결과 데이터 출력
        ↓
Node.js가 결과를 받아 HTTP 응답으로 반환
```

두 프로그램 사이에는 표준 입력(stdin), 표준 출력(stdout), 표준 오류(stderr)를 사용할 수 있습니다. 프로그램끼리 주고받을 데이터 형식을 JSON으로 정하면 구조화된 입력과 결과를 전달하기 쉽습니다.

## 8. Python 자식 프로세스 만들기

프로젝트 안에 `scripts` 폴더를 만들고 `scripts/fish_summary.py` 파일을 작성합니다. 이 Python 프로그램은 표준 입력에서 JSON을 읽고 요약 결과를 표준 출력으로 보냅니다.

```python
import json
import sys


def main():
    raw_input = sys.stdin.read()
    payload = json.loads(raw_input)

    observations = payload.get("observations", [])

    if not observations:
        result = {
            "count": 0,
            "averageWaterTemperature": None,
            "speciesCounts": {}
        }
    else:
        temperatures = [item["waterTemperature"] for item in observations]
        species_counts = {}

        for item in observations:
            species = item.get("species", "알 수 없음")
            species_counts[species] = species_counts.get(species, 0) + 1

        result = {
            "count": len(observations),
            "averageWaterTemperature": round(sum(temperatures) / len(temperatures), 1),
            "speciesCounts": species_counts
        }

    print(json.dumps(result, ensure_ascii=False))


if __name__ == "__main__":
    main()
```

`sys.stdin.read()`는 Node.js가 전달한 입력을 문자열로 읽습니다. `json.loads()`는 문자열을 Python 자료형으로 변환합니다. 마지막 `print()`는 결과 JSON을 표준 출력으로 보내며, `ensure_ascii=False`는 한글이 유니코드 이스케이프 형식으로 바뀌지 않게 합니다.

## 9. Node.js에서 Python 실행하기

`server.js` 상단에 `spawn`을 불러옵니다.

```javascript
const { spawn } = require("node:child_process");
```

다음 함수를 추가해 Python 프로세스를 실행하고 결과를 JSON으로 읽습니다.

```javascript
function runPythonSummary(payload) {
  return new Promise((resolve, reject) => {
    const pythonCommand = process.env.PYTHON_COMMAND || "python";
    const child = spawn(pythonCommand, ["scripts/fish_summary.py"]);

    let stdout = "";
    let stderr = "";

    child.stdout.setEncoding("utf8");
    child.stderr.setEncoding("utf8");

    child.stdout.on("data", (chunk) => {
      stdout += chunk;
    });

    child.stderr.on("data", (chunk) => {
      stderr += chunk;
    });

    child.on("error", (error) => {
      reject(error);
    });

    child.on("close", (code) => {
      if (code !== 0) {
        return reject(new Error(stderr || `Python 프로세스 종료 코드: ${code}`));
      }

      try {
        resolve(JSON.parse(stdout));
      } catch (error) {
        reject(new Error(`Python 결과를 JSON으로 읽지 못했습니다: ${stdout}`));
      }
    });

    child.stdin.end(JSON.stringify(payload));
  });
}
```

`spawn()`은 Python 프로그램을 별도의 프로세스로 실행합니다. Node.js는 표준 입력으로 JSON을 전달하고, 표준 출력에서 결과를 모읍니다. 종료 코드가 0이 아니면 실패로 처리하고, 성공했을 때는 표준 출력을 JSON으로 해석합니다.

운영체제에 따라 Python 명령 이름이 다를 수 있습니다. `python --version`으로 확인하고, 다른 명령을 사용해야 한다면 `.env`에 다음처럼 설정합니다.

```text
PYTHON_COMMAND=py
```

실행 환경의 Python 경로에 따라 `python3` 등을 지정할 수도 있습니다. 자식 프로세스를 실행할 때는 명령과 인자를 분리해 전달하고, 요청 본문을 명령 문자열에 이어 붙이지 않습니다.

## 10. 분석 API에서 자식 프로세스 호출하기

MongoDB에서 관측 데이터를 읽어 Python 분석 프로그램으로 전달하는 API를 `server.js`에 추가합니다.

```javascript
app.post("/api/analysis/summary", async (request, response, next) => {
  try {
    const { pondId } = request.body;

    if (!pondId) {
      return response.status(400).json({ message: "pondId가 필요합니다." });
    }

    const db = getDatabase();
    const observations = await db
      .collection("observations")
      .find({ pondId })
      .project({ species: 1, waterTemperature: 1, observedAt: 1 })
      .toArray();

    const summary = await runPythonSummary({ observations });

    response.json({ pondId, summary });
  } catch (error) {
    next(error);
  }
});
```

요청은 다음과 같이 보낼 수 있습니다.

```powershell
$body = @{ pondId = "pond-01" } | ConvertTo-Json

Invoke-RestMethod `
  -Method Post `
  -Uri "http://localhost:3000/api/analysis/summary" `
  -ContentType "application/json" `
  -Body $body
```

Node.js는 MongoDB에서 해당 양식장의 관측 데이터를 가져와 Python 프로그램에 전달합니다. Python은 관측 건수, 평균 수온, 어종별 건수를 계산합니다. Node.js는 Python 결과를 받아 브라우저에 JSON으로 응답합니다.

## 11. 오류와 프로세스 경계

Node.js와 Python은 서로 다른 프로세스이므로 한쪽의 오류를 다른 쪽이 자동으로 처리하지 않습니다. 다음과 같은 상황을 고려해야 합니다.

- Python 명령이나 스크립트 경로가 잘못된 경우
- Python 코드에서 예외가 발생한 경우
- 입력 JSON의 필드가 없거나 형식이 다른 경우
- Python이 JSON이 아닌 설명 문장을 표준 출력에 기록한 경우
- 분석 시간이 길어져 API 응답이 늦어지는 경우

표준 출력은 결과 JSON을 전달하는 데 사용하고, 디버깅 메시지는 표준 오류나 Node.js의 로그로 보냅니다. Python 프로그램이 실패했을 때 오류 메시지와 종료 코드를 기록하면 원인을 찾기 쉽습니다.

자식 프로세스 방식은 기존 Python 스크립트를 재사용할 때 유용합니다. 다만 매 요청마다 새로운 프로세스를 만드는 방식은 호출량이 많거나 모델을 메모리에 계속 올려 두어야 할 때 비효율적일 수 있습니다. 이후 수업에서는 FastAPI처럼 Python 모델을 별도 HTTP 서버로 제공하는 방식도 다룹니다.

## 실습: 수산물 API와 Python 요약 기능 연결하기

앞에서 만든 API 서버를 기반으로 다음 기능을 완성합니다.

- MongoDB에 `observations` 컬렉션을 사용합니다.
- 수산물 관측 데이터의 등록과 목록 조회를 구현합니다.
- 상세 조회·수정·삭제 API를 추가합니다.
- 필수 필드와 ID 형식을 검사하고 적절한 상태 코드를 반환합니다.
- Python 스크립트가 JSON 입력을 읽고 관측 요약 JSON을 출력하도록 만듭니다.
- Node.js 자식 프로세스를 실행해 Python 결과를 API 응답으로 전달합니다.

## 오늘의 미션

- MongoDB 문서 형태로 수산물 관측 데이터를 설계합니다.
- Express와 MongoDB를 연결합니다.
- 관측 데이터 CRUD API를 실행하고 요청·응답을 확인합니다.
- Node.js의 `spawn()`으로 Python 스크립트를 실행합니다.
- 표준 입력과 표준 출력으로 JSON을 주고받습니다.
- Python 오류 또는 잘못된 JSON 결과가 발생했을 때 Node.js가 오류 응답을 반환하도록 합니다.

## 핵심 정리

- MongoDB는 데이터를 컬렉션 안에 문서 형태로 저장합니다.
- Express API는 MongoDB 드라이버를 통해 데이터 생성·조회·수정·삭제를 수행할 수 있습니다.
- 요청 데이터를 저장하기 전에 필수 값, 자료형, ID 형식을 확인해야 합니다.
- Node.js의 `child_process.spawn()`은 별도의 Python 프로세스를 실행할 수 있습니다.
- 표준 입력과 표준 출력에 JSON을 사용하면 Node.js와 Python 사이에서 구조화된 데이터를 주고받을 수 있습니다.
- 자식 프로세스의 오류, 종료 코드, 출력 형식을 함께 확인해야 합니다.
- 다음 수업에서는 해양 공공데이터를 정제해 MongoDB에 적재합니다.
